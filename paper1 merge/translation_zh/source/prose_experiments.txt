@@ experiments.001

\paragraph{模型构建的图。}
Claude Haiku 为相同的 225 篇测试文档分别构建新图。输入为源文本、文档编号和允许关系。评分器将结构化字段作为参考值。十个响应的 JSON 无效，按空图计分，解析成功率为 95.56\%。共有 77 张图与参考不同，包含 302 项三元组差异。两名评审检查其中固定抽样的 200 项差异，第三名评审解决分歧（第~\ref{sec:eval:human}~节）。

@@ experiments.008
\paragraph{修复方法。}
所有方法获得相同输入图、源文本、文档编号和允许关系。
\begin{itemize}
    \item \textbf{Source-field Copy}：读取字段标签，直接从文本复制值。
    \item \textbf{No Repair}：返回输入。
    \item \textbf{Rule Only}：去重，将指向文档节点的边反向，删除非法头节点和关系。
    \item \textbf{SHACL-style Repair}：使用 SHACL 形状约束检查文档头节点和允许关系\citep{ref_shacl2017}。
    \item \textbf{Direct LLM}：调用一次模型，根据原文返回完整图。
    \item \textbf{ReAct-style Agent}：一次调用查找错误，另一次调用执行修复\citep{ref_yao2023react}。
    \item \textbf{Simple Pipeline}：清理输入，调用一次模型，并对响应去重。
    \item \textbf{Diagnosis + Gate}：在提示中增加错误报告，按文档编号、关系、来源匹配、重复数量和每字段值数量过滤输出。
\end{itemize}

@@ experiments.018

接下来，我们测试索引提示中的哪些部分影响字段选择。六种提示设置使用相同的 60 张新测试收据。这一独立批次包含与组件测试一起收集的 360 个新 Gemma 响应。所有响应都能解析。各设置均保留完整来源，并共享模型、输出上限和过滤器。随机索引与完整索引的字符长度接近。

@@ experiments.104
完整索引的 F1 比 Simple 高 4.35 个百分点（95\% 置信区间：1.25 至 7.86）。五项预设比较的 Holm 校正值为 $p_H=0.065$。完整索引与仅锚点行的平均 F1 相同。完整索引与随机索引相差 1.85 个百分点（置信区间：$[-0.65,4.52]$；$p_H=0.696$）。去掉字段含义使完整索引 F1 下降 8.81 个百分点（置信区间：$[4.23,13.39]$；$p_H=0.006$）。本批次 Simple 去掉字段含义后得分更高。这些结果说明字段含义有助于索引提示选择取值。

@@ experiments.105
在这一批次中，仅锚点行与完整行窗口取得相同平均分数；完整索引与随机索引的差值区间同时包含正值和负值。字段含义在索引提示中发挥了明确作用，而在 Simple 中的影响方向相反。因此，上下文的作用取决于字段说明与行提示如何共同呈现。

@@ experiments.112
为测试已有图的作用，我们在 60 张新测试收据上使用四种设置：带或不带索引的修复与重新抽取。各设置共享来源行、字段含义、文档编号和输出上限，修复还接收已有图。全部 240 个响应都将 JSON 放在 Markdown 围栏中，固定的严格解析器将它们计为失败，因此每种设置的 F1 均为零。

@@ experiments.113
在收集后的单独分析中，我们去掉围栏，并为每个输出赋予已知文档编号，对这些保存响应重新计分。索引修复的 F1 为 83.93\%，索引重新抽取为 74.86\%。配对差值为 9.07 个百分点（95\% 区间：5.22 至 13.10）。在这一评分规则下，已有图帮助生成更多匹配的字段值。建图成本与修复分开计算。附录~\ref{app:reextraction_diagnostics}~给出解析步骤、编号错误和来源行覆盖情况。

@@ experiments.115
合同测试在另一项字段任务上考察相同修复思路，将修复同时与输入图和重新抽取比较，从而衡量修改已有图带来的收益和损失。

@@ experiments.116
我们用 CUAD\citep{ref_cuad} 测试五个字段：文档名称、签约日期、生效日期、到期日期或初始期限，以及适用法律。选择空白清理后每字段最多一个不同参考值、原文不超过 40,000 字符的合同。保留完整原文，并检查标注值的位置。20 份官方训练合同构成开发集；全部 56 份满足规则的官方测试合同构成测试集。

@@ experiments.117
比较初始抽取、Simple 修复、索引修复和索引重新抽取。两种修复方法得到相同初始图，索引方法在完整原文之外增加字段行窗口。各设置共享 Gemma 模型、字段含义和 4,000 token 输出上限。采集前，程序已设置 JSON 围栏处理和文档编号分配。一轮开发之后，提示与选择规则保持固定。

@@ experiments.119
索引修复 F1 为 44.84\%，输入为 46.76\%，下降 1.92 个百分点。它删除五条正确输入事实，并增加十二条与参考不同的事实。Simple 修复也低于输入。

@@ experiments.120
索引修复的 F1 比索引重新抽取高 0.72 个百分点（95\% 配对置信区间：[-4.80,6.48]；符号翻转检验 $p=0.810$）。测试共用 270 次请求得到 224 个输出，包括重试。失败输出计为空图。评分在空白清理后，将复制文本与 CUAD 标签比较。

@@ experiments.122
输入图在这些设置中取得最高 F1。两种修复方法都丢失了正确输入事实，索引修复还增加了与参考不同的值。它相对索引重新抽取的小幅领先，其区间同时覆盖两个方向。收据上的收益在这项合同任务上变成了相对输入的下降。这些结果指出，保留正确字段和选择与标注一致的文本片段，是主要修复目标。

@@ experiments.124
人工评价考察自动评分背后的两项判断：参考差异在上下文中是否属于错误，以及某项编辑在输出图中是否可接受。前者针对输入事实，后者还考虑操作对图的影响。

@@ experiments.125
任务 D 从模型构建输入的 302 项三元组差异中抽取 200 项参考差异。任务 E 从五种设置的 598 项编辑中抽取 200 项实际编辑。两者都用种子 42 随机抽样。每项是一项差异或编辑，同一文档可提供多项。评审看到原文、模式、输入图和指定操作。任务 E 还展示完整输出图。方法名称与参考质量提示隐藏。

@@ experiments.126
两名具有计算机背景和中文阅读能力的评审先阅读规则和练习样例，再各自独立标注相同的 400 项。每项回答两个问题：输入在该位置是否有错（\texttt{is\_error}），以及添加或删除操作是否可接受（\texttt{repair\_acceptable}）。标签为 0、1 或 U，并说明理由。U 表示所示证据不足以作出判断。第三名评审检查原文和图，在两人的答案中选择，解决 154 项分歧。其余 246 项保留一致标签。一项编辑接受判断仍为 U。原始标签和一致性分数均保留。

@@ experiments.128
评审在 95/200 项参考差异中发现输入错误，接受 86/200 项建议编辑，以及 134/199 项实际编辑，另有一项不确定。一个缺失值本身可以是正确的，但添加后可能使仅允许一个值的字段出现两个值。输入错误与编辑接受问题分别覆盖这两个判断。任务 E 的原始编辑一致率为 65.0\%，$\kappa=0.128$。

@@ experiments.130
表~\ref{tab:human_review_by_config}~报告各设置的样本量和可接受编辑数，合并接受率汇总这些组。两个人工问题得到不同结果，因为即使值本身正确，添加方式也可能违反字段规则。原始一致性分数表明，与识别输入错误相比，评审对编辑接受判断的分歧更大。标签和理由共同帮助定位字段选择与编辑执行中的问题。

@@ experiments.132
\paragraph{来源格式与字段选择。}
中文记录直接给出字段名和值，因此 Source-field Copy 可以匹配参考。收据需要在文档中的多个值之间选择。在新收据测试中，索引提示改善了这一选择，收益在过滤前就已出现。上下文对照表明，字段含义与行提示共同发挥作用。合同则呈现不同结果：修复丢失了正确输入匹配，最终低于初始图。来源格式与保留正确输入字段的能力共同影响修复价值。

@@ experiments.133
\paragraph{检查与字段含义。}
输出门控删除未通过来源与文档编号检查的三元组。为关系选择正确的来源值，则是修复的另一项工作。收据中可能同时出现小计和最终金额，两者都在文本中。字段含义决定哪一个属于“总额”。人工评价在精确参考匹配之外考察这些上下文，并检查最终编辑是否符合图的字段规则。

@@ experiments.134
\paragraph{评估与下一项编辑。}
评估概况将检测到的问题连接到生成和动作选择。匹配测试中，错误报告组的平均 F1 更低；选择器日志则显示，一些有用编辑被接受评分拒绝。这些结果指出两个具体设计目标：报告应帮助模型选择字段值，试改评分应在质量和编辑成本之外计入缺失字段恢复的收益。表~\ref{tab:research_answers}~汇总三个问题的答案。
