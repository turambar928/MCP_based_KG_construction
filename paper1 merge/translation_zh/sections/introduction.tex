\section{引言}
\label{sec:introduction}

知识图谱（KG）连接不同来源的事实，支持问答、推荐和数据分析\citep{ref_ji2021,ref_pan2023}。这些应用依赖所存事实的质量。关系缺失会使有用的信息无法被发现，错误取值则可能导致错误答案或决策。随着更多图谱从文本构建，检查和提高图谱质量已成为知识图谱构建的重要部分\citep{ref_zaveri2016,ref_paulheim2017}。其目标是恢复有用事实，并保留图中已有的正确信息。

从文本抽取事实后，同一张图中会留下多类错误。来源噪声和含义不清的表述可能造成字段缺失、事实重复、关系错误，以及取值被放入错误字段\citep{ref_ji2021,ref_paulheim2017}。这些错误将图结构与源文本的含义联系起来。例如，收据上可能同时出现小计和最终金额，但两者的作用不同。判断某个金额是否属于总额字段，需要检查它是否出现在原文中，也需要判断它的含义。因此，图修复需要同时检查结构和字段取值的来源证据。

现有方法从不同方面提高图谱质量。基于规则的检查发现违反图规则和字段要求的情况\citep{ref_kontokostas2014,ref_shacl2017}。嵌入模型根据图中的模式，为事实成立的可能性打分\citep{ref_bordes2013,ref_nickel2016}。大语言模型（LLM）利用文本和图上下文提出修复建议\citep{ref_pan2023,ref_lin2025}。每类方法都为修复决策提供有用信息。规则违规指出了未满足的要求，模型建议则给出可能的替换内容。将这些信号连接起来，需要统一描述错误、明确修改边界，并在修复动作之间作出选择。

质量错误出现在不同尺度。局部检查可以发现重复事实，图检查则检验关系和字段间的冲突。来源检查将保存的取值与文档证据联系起来\citep{ref_zaveri2016,ref_wang2021}。一个值可能满足字段规则，却指向文档中的错误位置。因此，规划修复时需要汇总这些检查。我们提出覆盖实体、图和上下文尺度的\emph{多尺度质量评估}。各项检查形成共享的评估概况，记录不同范围内的错误和质量分数。这一概况将发现的问题传入修复过程，并为评估修改建议提供统一依据。

修复还需要在恢复缺失事实与保留正确事实之间作出权衡。添加事实可能引入字段冲突，删除事实则可能损失有用信息。我们提出\emph{约束驱动优化}，为这些修改设定清楚的边界。来源和字段约束决定哪些生成的三元组可以进入修复后的图。在编辑选择中，质量下界和密度上限限定允许的试改图，编辑成本则鼓励小幅修改。这些约束将修复目标与明确的输出要求联系起来，也使接受或拒绝修改建议的依据清晰可查。

修复动作的选择也需要反映错误类型。简单规则可以删除重复事实并修正明确的结构错误。缺失值或错误值则需要阅读源文本。多个编辑建议可能针对同一字段，也可能改变另一项编辑的效果。我们提出\emph{尺度感知路由}，利用评估概况引导选择。小型神经模型为实体、图和上下文尺度的编辑赋予权重。选择器将这些权重与质量收益、编辑成本结合，在图边界内比较修改建议。每次接受编辑后，重新评估图谱，再引导下一次选择。这样，发现的问题范围与修复范围及成本建立了联系。

上述设计将评估、修复约束和动作选择连接为一个框架。本文研究文档图谱，其字段需要遵循给定模式，并从可用源文本中取值。主路径结合规则清理、大语言模型生成和输出过滤。错误报告或按字段提供的来源行提示引导生成。路由路径每次选择一项编辑，并在每次接受修改后检查图谱。我们为生成路径和路由路径中的组件分别设置对照。这一设计展示各项方法在修复不同阶段对图谱的影响。

实验覆盖三个中文记录集合、SROIE 收据和 CUAD 合同，并对图谱差异和系统编辑开展人工评价。在含有 450 个注入缺陷的 225 张图上，诊断＋门控 修复了 98.00\% 的缺陷。在模型构建的图上，它将三元组 F1 从 87.99\% 提高到 92.48\%。在新测试的 60 张收据上，来源行提示使 F1 比 简单流程 高 4.76 个百分点。共享提示对照和组件测试分析生成、过滤、证据上下文和编辑选择的作用。评价同时记录字段恢复、事实保留、请求成本和人工编辑接受度。

本文有三项贡献：
\begin{itemize}
    \item \textbf{多尺度质量评估。}
    我们将局部结构、图规则和来源检查汇入共享概况，将发现的缺陷与修复决策联系起来。
    \item \textbf{约束驱动修复与尺度感知路由。}
    我们为生成的图定义来源和字段约束。神经路由路径为候选编辑赋予权重，并在图边界内比较其质量收益和成本。
    \item \textbf{文档图谱评价。}
    我们在注入缺陷、模型输出、收据和合同上比较修复方法及其组件，并开展人工评价。保存的输出和决策日志支持检查各个修复阶段。
\end{itemize}
