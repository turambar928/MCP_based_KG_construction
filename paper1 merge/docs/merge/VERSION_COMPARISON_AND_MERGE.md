## 3. 老师意见主要改善了什么

### 从列步骤，变成先提出问题

合并前的方法开头直接介绍输入，然后写“清理输入、生成完整图、过滤三元组”。读者很快知道程序做什么，但检查、约束和路由为什么放在一起，解释较少。

老师在 `method.tex` 第 23 行要求说明：“why we have this module. how we connect the problem with the solution.” 第 75 行又提出：“what to update and how to update?”

我据此重写了引言和方法开头。现在先讲三个问题：检查什么、留下哪些修改、下一步选哪个编辑。方法开头用两句短句连接检查与修复：

> Graph repair needs two linked steps: find a problem, then choose a change.
> We join a graph-check module with a repair module.

例如重复记录用局部检查，非法字段用图规则检查，来源不符的值用原文检查。这样，读者能从错误类型理解模块的用途。

### 把“网络是什么”放到“为什么需要选择”之后

老师希望先说明：多个修复动作可能冲突，也有不同成本，因此需要选择。网络的大小和训练细节应放在这个目的之后。第 81、83、118 行批注都围绕这个顺序。

合并前版本已经有路由器、候选编辑、成本和试改评分。此次将这些内容集中到 4.3，顺序变为：

1. 为什么要决定下一步改哪里。
2. 当前图的四个分数和四个统计量。
3. 网络输出修复分数和三类编辑权重。
4. 网络结构与训练标签。
5. 添加、删除、改关系及其成本。

随后在 4.4 说明怎样试改、检查、执行和停止。新增的 Algorithm 2 把这一过程连起来。这里主要补齐论文解释，程序和模型沿用已有实现。

### 让术语和公式承担明确的作用

老师指出 quality state vector 与 quality assessment profile 的称呼不一致。我统一使用 assessment profile，并在正文解释它的两种具体形式：主流程用错误报告 `D`，逐次选择器用四项分数 `s`。

公式也按用途排列。字段检查回答“候选是否符合来源和字段规则”；数量公式回答“过滤后留下多少条”；编辑评分回答“这次修改值不值得做”；选择公式回答“允许的编辑中选哪一个”。重要公式后都接一段短解释。

原有三张 PDF 方法图继续使用。阅读顺序调整为检查范围图、路由框架图、试改循环图，分别为 Figures 1、2、3。图片内容保持原样，图注和放置位置与新行文对应。

## 4. 哪些地方按当前实现重新写了

### 两条修复路径分别说明

这是合并中最重要的结构取舍。

老师稿把“评估—路由—执行—再次评估”作为统一的循环来讲。合并前版本的主实验则使用“清理—一次模型生成—过滤”。逐次选编辑的路由器有另一组独立测试。

合并版保留老师关于检查、约束和选择的组织思路，同时写清这两条路径：

| 路径 | 实际步骤 | 对应结果 |
|---|---|---|
| 生成与过滤 | 清理输入，生成完整图，检查每条候选 | 主流程的修复率、F1，以及提示和过滤对照 |
| 路由与逐次选择 | 计算 profile，给编辑权重，复制图试改，选一项执行，再次检查 | 选择器、成本、先验和边界的独立测试 |

例如，98.00% 的缺陷修复率对应第一条路径。第二条路径的效果在 5.4 和附录 A.2 中报告。这样，方法描述、算法和实验配置可以直接对上。

**合并版仍以文档字段修复为具体任务。老师稿中更广的多工具、跨文档循环框架，没有整体替换当前任务定义。**

### 检查范围、训练和执行采用当前定义

下面几处涉及算法含义，需要按代码处理。

| 项目 | 老师文件中的写法 | 合并版采用的写法与原因 |
|---|---|---|
| 上下文检查 | 跨文档因果、过程关系，以及路径和 LLM 评分 | 当前任务的 context 指文档原文；选择器按来源匹配计分，与已有代码对应 |
| 重复判断 | 加权嵌入相似度 | 使用字符对计数的余弦相似度，权重为 0.4、0.2、0.4，阈值为 0.92 |
| 路由训练标签 | 检查器生成修复标签，按违规数得到 scope 分布 | 已知注入缺陷提供标签；主要缺陷类别训练 scope 输出，干净图只训练修复输出 |
| 修复动作来源 | 外部检索、规则推理、LLM 推理等工具 | 当前选择器使用规则候选和保存的模型提议，动作是添加、删除和改关系 |
| 修改收益 | 用局部邻域估计质量增益 | 复制图试改，再重新计算完整图的 profile |
| 触发与停止 | 低修复概率即停止，并描述五轮内收敛 | 已提供候选或存在硬规则错误时继续试改；无正分允许编辑等条件下停止，测试上限为 12 轮 |

网络的 8→32→16 结构、884 个参数，以及删除 0.30、改关系 0.16、添加 0.06 的成本，都来自已有实现。这轮补充的是说明和公式，没有重新训练或调整参数。

### 优化公式落到实际选择步骤

老师稿用“在约束下寻找质量最高的图”组织公式。合并前版本已经给出字段过滤的数量公式，以及包含质量差、规则错误减少、成本、先验和置信度的编辑评分。

我保留了这两部分，并把选择器的优化写成：**在当前允许的候选编辑中，选得分最高且大于零的一项。** 四项下界、允许回退幅度、密度上界和非空要求决定哪些试改可以进入选择。

因此，老师“用约束界定修改范围”的思路保留了下来，公式描述的是代码实际执行的步骤。这里也保留了合并前版本已有的完整评分，没有换回老师文件中较简略的旧评分。

## 5. 实验与贡献怎样处理

老师文件中保留了综合质量提高 8.89 点、多尺度融合提高 2.30 点等旧结果。合并前版本已经使用另一套任务和报告方式，包括缺陷修复率、三元组 F1、保留的正确字段及人工接受率。这些数字的指标和比较条件不同。

本次实验正文和附录直接沿用当前基稿，逐字节保持一致。摘要与结论也保留当前数字。例如：

| 当前结果 | 合并后怎样使用 |
|---|---|
| 225 个受控图、450 个缺陷，主流程修复率 98.00% | 说明生成与过滤路径在该任务中的修复结果 |
| 模型抽取图的 F1 从 87.99% 到 92.48% | 说明主流程在模型输出上的变化 |

旧数字继续留在原历史文件中。本轮没有追加实验，也没有把不同版本的结果合成一个新的成绩。

引言贡献则重新组织了。合并前的三项贡献主要是修复流程、评价覆盖和组件对照。合并后写为：汇总三类检查的 profile；带输出过滤和独立选择器的修复设计；覆盖不同任务、人工评价和日志的组件比较。

这样，老师关注的方法结构进入贡献陈述，现有实验仍按实际配置说明各部分的效果。选择器的结果继续单独报告。
