\section{Introduction}
\label{sec:introduction}

Knowledge graphs (KGs) connect facts across sources and support question
answering, recommendation, and data analysis \citep{ref_ji2021,ref_pan2023}.
Large language models (LLMs) make it easier to build these graphs from
text \citep{ref_pan2023}.
As more documents enter a graph, its value depends on whether the stored
facts are correct, complete, and consistent \citep{ref_zaveri2016,ref_paulheim2017}.

Text extraction can leave missing fields, repeated facts, wrong relations,
and values placed in the wrong fields \citep{ref_ji2021,ref_paulheim2017}.
These errors concern both graph structure and the meaning of the source text.
For example, a receipt can contain a subtotal and a final amount.
Both values occur in the text, yet only one belongs in the total field.
Repair therefore needs to locate the error and find evidence for the proposed value.

Rules check graph and field requirements \citep{ref_kontokostas2014,ref_shacl2017}.
Embedding models score facts from graph patterns \citep{ref_bordes2013,ref_nickel2016}.
LLMs use text and graph context to suggest changes \citep{ref_pan2023,ref_lin2025}.
A repair process must turn these different signals into a clear decision.
It must decide what needs repair, which changes are allowed, and which edit
should be applied next.
Adding a missing fact can create a field conflict, while deleting a fact can
remove correct information.

Our idea is to link these decisions through a shared assessment profile.
The profile records the errors, constraints set bounds on changes, and
edit selection uses both to guide repair.
We build a framework around this link, combining multi-scale quality
assessment, constraint-driven repair, and scale-aware routing.
This connects the kind of error with the scope and cost of its repair.

We support this idea with \emph{Multi-Scale Quality Assessment} and
\emph{Constraint-Driven Optimization}.
Entity checks find local errors, graph checks test field and relation rules,
and context checks use the original document \citep{ref_zaveri2016,ref_wang2021}.
These checks form the shared profile.
The main repair path cleans the input, asks an LLM for a complete graph,
and filters the proposed triples.
Field rules and source matches decide which triples enter the output.
The profile or field-specific source-line hints guide the model.

\emph{Scale-Aware Routing} supports a second path that chooses edits one at a time.
A small neural model uses the profile to weight edits at the entity, graph,
and context scales.
The selector tests candidate edits on graph copies, compares their quality
gains and costs, and accepts an edit that meets graph bounds.
It then updates the profile for the next decision.

Experiments show that the main pipeline repairs 98\% of added defects in
Chinese records and that source-line hints raise receipt F1 over Simple
Pipeline by 4.76 points.
