# 政务知识图谱质量评估工具使用指南

## 概述

本工具专门为政务领域的知识图谱质量评估而设计，针对政务文本的特点进行了优化，包括政府机构层级关系检测、地理层级关系检测、政务术语准确性评估等功能。

## 主要特性

### 1. 政务领域专用规则
- **政府机构层级关系检测**：检测是否存在下级机构管理上级机构的逻辑错误
- **地理层级关系检测**：验证地理区域的管辖关系是否合理
- **政务术语准确性**：评估是否使用了正确的政务专业术语
- **行政逻辑一致性**：检查政策适用范围、服务事项主体等是否符合行政逻辑

### 2. 多维度质量评估
- **节点连通性 (25%)**：评估政务实体间的关联完整性
- **三元组唯一性 (25%)**：检测重复的政务关系表述
- **逻辑一致性 (25%)**：评估政务层级关系、地理关系等的逻辑合理性  
- **语义合理性 (25%)**：评估政务关系表述的专业性和准确性

### 3. 智能质量等级判定
- **90-100分：优秀** - 图谱质量很高，可直接应用
- **80-89分：良好** - 图谱质量较好，少量问题需要修正
- **70-79分：中等** - 图谱质量一般，存在一些质量问题
- **60-69分：及格** - 图谱可用但需要大量改进
- **<60分：不合格** - 图谱质量较差，需要重新构建

## 使用方法

### 基本用法
```bash
cd data
python evaluate.py --node-files 节点文件.csv --rel-files 关系文件.csv --output-dir 输出目录
```

### 完整参数示例
```bash
# 评估政务知识图谱（包含语义评估）
python evaluate.py \
    --node-files 政务_nodes.csv \
    --rel-files 政务_relationships.csv \
    --output-dir 政务_评估报告 \
    --api-key YOUR_ZHIPUAI_API_KEY \
    --sample-size 0.1

# 快速评估（跳过语义评估，节省API调用）
python evaluate.py \
    --node-files 政务_nodes.csv \
    --rel-files 政务_relationships.csv \
    --output-dir 政务_评估报告 \
    --no-semantic

# 评估多个文件
python evaluate.py \
    --node-files 文件1_nodes.csv 文件2_nodes.csv \
    --rel-files 文件1_relationships.csv 文件2_relationships.csv \
    --output-dir 合并_评估报告
```

### 命令行参数详解

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--node-files` | 节点CSV文件路径列表 | `./政务_nodes.csv` |
| `--rel-files` | 关系CSV文件路径列表 | `./政务_relationships.csv` |
| `--output-dir` | 报告输出目录 | `./qa_report` |
| `--api-key` | 智谱AI API密钥 | 配置文件中的密钥 |
| `--sample-size` | 语义评估采样比例 (0-1) | `0.1` |
| `--no-semantic` | 跳过语义评估（节省API调用） | 否 |

## 输出文件说明

评估完成后，在输出目录中会生成以下文件：

### 主要报告文件
- **`report.txt`** - 完整的评估报告，包含各维度得分和质量等级
- **`quality_scores.json`** - 评估分数的JSON格式数据

### 问题详情文件
- **`isolated_nodes.csv`** - 孤立节点列表
- **`redundant_triples.csv`** - 冗余三元组列表  
- **`logical_conflicts.csv`** - 逻辑冲突详情（包含政务层级冲突）
- **`semantic_evaluation.csv`** - 语义评估详情（如启用）
- **`all_issues.csv`** - 所有问题的汇总

## 政务领域特有的检测规则

### 1. 政府机构层级关系
系统会检测以下层级顺序是否合理：
```
国务院 > 省政府 > 市政府 > 县政府 > 乡镇政府 > 街道办事处
```

**示例冲突：**
- ❌ "乡镇政府" --[管理]--> "省政府"
- ✅ "省政府" --[管理]--> "市政府"

### 2. 地理层级关系
检测地理区域的管辖关系：
```
国家 > 省/自治区/直辖市 > 市/州 > 县/区 > 乡镇 > 村/社区
```

**示例冲突：**
- ❌ "村" --[管辖]--> "县"
- ✅ "县" --[管辖]--> "村"

### 3. 政务关系类型检测
允许的政务关系包括：
- 政府机构：隶属于、管理、监管、发布、提供
- 政策法规：适用于、规范、约束、保护
- 服务事项：属于、需要、收费标准
- 地理关系：位于、管辖、实施

## 配置定制

可以通过修改 `evaluate.py` 中的 `CONFIG` 来定制评估规则：

```python
CONFIG = {
    "logical_rules": {
        "不允许的节点类型": ["NONE", ""],
        "无效关系类型": ["NONE", "", "未知关系"],
        "类型冲突规则": {
            # 添加自定义规则
            ("新实体类型", "新关系", "目标类型"): "允许"/"禁止"
        }
    }
}
```

## 常见问题

### Q: 为什么逻辑冲突比例很高？
A: 可能原因：
1. 实体类型分类不准确（大多数被标记为Unknown）
2. 政务层级关系提取有误
3. 需要调整评估规则以适应具体的数据特点

### Q: 如何提高评估准确性？
A: 建议：
1. 改进知识图谱构建过程中的实体分类
2. 根据具体政务领域调整逻辑规则
3. 启用语义评估以获得更全面的质量评估

### Q: 语义评估消耗API调用怎么办？
A: 
1. 使用 `--no-semantic` 跳过语义评估进行快速评估
2. 调整 `--sample-size` 参数减少采样比例
3. 只在最终评估时启用语义评估

## 最佳实践

1. **分阶段评估**：在知识图谱构建的不同阶段进行评估
2. **增量评估**：结合实时增量写入功能，监控质量变化
3. **规则调优**：根据评估结果调整逻辑规则和检测阈值
4. **问题追踪**：重点关注 `logical_conflicts.csv` 中的问题模式
5. **持续改进**：基于评估反馈优化知识抽取流程
