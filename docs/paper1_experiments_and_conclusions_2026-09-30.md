## 1. 先理解整篇论文到底在验证什么

Paper1 研究的是：已从文档生成一个字段型知识图谱后，如何利用原文、字段定义和约束改善输出。典型图以文档为中心，关系表示公司名、日期、地址、金额或合同字段，尾节点通常是字段值。它与包含大量实体间关系的通用连通知识图谱有区别。

仓库里存在三条相关但不同的执行路径：

|路径|实际做什么|对应实验证据|
|---|---|---|
|单次生成与过滤|预处理输入图；给模型原文和可选诊断；模型返回完整候选图；检查文档头、关系、来源跨度、重复和字段数量|225 文档主实验、自然抽取实验、匹配上下文、收据实验|
|证据索引辅助|在相同来源和字段定义之外，提供与字段相关的锚点及附近来源行|收据后续测试、索引对照、CUAD 合同实验|
|神经先验与顺序选择器|使用图谱 profile 预测动作尺度偏好，逐个试做候选编辑，按质量、约束、成本和效用选择|旧版回放、共享特征 v2、13 组组件消融|

**98.00% 缺陷修复率属于第一条路径，不能拿来证明第三条路径的神经选择有效。** 同样，收据上索引的增益不能自动证明跨文档推理、因果验证或大型连通图修复。

目前实验形成的主线是：先看完整修复流程能否改善输出，再检验收益来自哪一部分，最后换文档类型检查是否还能成立。

中文证据文本由结构化字段拼接成“字段名：值”的形式；大多数字段值最多保留 320 字符，服务名称最多 100 字符。同样的规范化值定义参考图。因此，来源已经直接暴露答案，Source-field Copy 能取得满分有明确的数据原因。

## 3. 指标分别回答什么问题

### 3.1 修复率、F1、整图精确匹配不是同一个指标

- **缺陷修复率**：针对注入记录中的目标缺陷，要求恢复对应的干净三元组及其重数，并消除损坏形式。主表分母是 450 个受控缺陷。
- **三元组 F1**：衡量输出与参考图的整体重合，既考虑漏项，也考虑额外错误项。文档级 F1 通常先逐文档计算，再取平均。
- **整图精确匹配**：整个图都与参考一致才记为成功，要求比 F1 更严格。
- **正确事实保持**：输入中原本与参考相符的事实，修复后还有多少保留。保持率高不保证补回了缺失事实。
- **过度修复**：检查修复额外带来的错误；各实验按自己的冻结评分器计算，不将不同任务的列直接合并。

对于集合记法，F1 为：

\[
\mathrm{F1}=\frac{2|G_{\mathrm{out}}\cap G^*|}{|G_{\mathrm{out}}|+|G^*|}.
\]

受控主实验还关注重复项，使用多重集及缺陷重数；不能用简单集合去重后声称重复缺陷全部修好。CUAD 的评分则是空白规范化后的“关系—值”集合。比较各表前要先看对应评分口径。

### 3.2 自然输入的错误减少率

设多重集差异数为 \(d\)，则：

\[
1-\frac{d(G_1,G^*)}{d(G_0,G^*)}.
\]

它只在原本不精确的 77 个中文图上平均，因为初始完全正确的图分母为零。负数意味着新增差异超过消除的差异。例如 −59.15% 不表示 F1 为负，而是平均错误减少率为负。逐文档平均比值也不等于先汇总所有错误再算一个比值。

### 3.3 精确匹配与语义正确性

收据里的 `1,200.00`、`1200.00`、不同大小写或地址换行，可能表达相同内容，却不满足严格字段匹配。因此同时报告规范化 F1 和金额专项检查。CUAD 使用源文跨度匹配，也会受到字段边界和表达形式影响。

这些指标具有明确可复现性，但不能替代对实际编辑的真人语义审查。SROIE/CUAD 自带人工标签，也不等于论文新做了系统编辑的独立双人标注。

### 3.4 显著性如何读

论文多处使用文档配对 bootstrap：同一文档在不同方法之间一起重采样。一个文档的两个缺陷、四个字段不能任意当作独立文档。

95% 区间跨零意味着当前数据未提供可靠方向证据，不表示两方法已经被证明等效。预设多项比较使用 Holm 校正；单项区间不跨零也可能在校正后不显著。历史探索性检验、事后诊断与冻结主比较在下文分别标识。

## 4. 受控中文主实验：完整流程能修好多少已知缺陷

### 4.1 设计

六类缺陷是缺失三元组、重复三元组、非法关系、反向边、不受来源支持的值和层级冲突。每个文档恰好注入两个有效变化。先按来源划分，再构造损坏图，避免同一文档的干净／损坏版本跨训练与测试。

历史模型实验使用同一个 Claude Haiku checkpoint、温度零。Direct LLM 为一次调用；ReAct-style 为先诊断后执行的两次调用；Simple Pipeline 与 Diagnosis + Gate 都使用一次生成，但提示内容及后处理不同。这个 ReAct 实现不是所有强 agent 的代表。

### 4.2 结果

|方法|缺陷修复率|正确事实保持|过度修复|三元组 F1|整图精确匹配|调用/文档|
|---|---:|---:|---:|---:|---:|---:|
|Source-field Copy|100.00%|100.00%|0.00%|100.00%|100.00%|0|
|No Repair|0.00%|100.00%|0.00%|76.15%|0.00%|0|
|Rule Only|32.00%|100.00%|0.00%|84.72%|6.22%|0|
|SHACL-style Repair|0.00%|100.00%|0.00%|79.98%|0.00%|0|
|Direct LLM|92.44%|96.87%|7.58%|95.20%|82.67%|1|
|ReAct-style Agent|89.11%|93.24%|16.67%|92.13%|59.56%|2|
|Simple Pipeline|95.11%|97.23%|7.05%|96.34%|84.00%|1|
|Diagnosis + Gate|98.00%|99.32%|1.67%|99.17%|93.33%|1|

该批历史请求的每文档平均耗时为：Direct 7.25 秒、ReAct 20.50 秒、Simple 9.27 秒、Diagnosis + Gate 11.44 秒。两调用没有自动带来更高质量；完整流程与 Simple 虽然都是一调用，耗时和输入内容也不同。

Diagnosis + Gate 相对 Simple 的修复率高 2.89 个百分点，文档配对区间为 [1.11, 4.89]；F1 高约 2.84 点，区间 [1.65, 4.25]。模型方法之间有实际差别。

### 4.3 应得出的结论

完整单次修复流程能在这类受控字段任务上达到较高恢复率，且比所实现的 Direct、Simple 和两调用 ReAct 流程更好。但最强结果是无需模型的字段复制：因此本实验没有证明此任务必须使用 LLM，更没有证明复杂神经选择器是 98% 修复率的来源。

SHACL-style 的低修复率描述的是本实验采用的有限 shapes 和修复操作，不能写成 SHACL 语言不能表达复杂约束。

依据：[当前实验正文](../paper1/sections/experiments.tex)、[补充对照报告](../exps/paper1_submission_extensions/report.md)。

## 5. 实际模型抽取错误：提升是否只来自修复 JSON

### 5.1 设计与整体结果

对同一批 225 来源进行真实模型抽取，不人为注入缺陷。10 份响应无法解析，保留为空图；总解析成功率 95.56%。77 个图与参考不一致，共 302 个多重集三元组差异。

|方法|三元组 F1|整图精确匹配|77 个不精确输入上的平均错误减少率|
|---|---:|---:|---:|
|初始抽取图|87.99%|65.78%|0.00%|
|Simple Pipeline|88.07%|67.11%|−59.15%|
|Diagnosis + Gate|92.48%|68.44%|27.75%|
|Source-field Copy|100.00%|100.00%|100.00%|

Diagnosis + Gate 相比 Simple 的 F1 高 4.40 点，95% 区间 [3.07, 5.77]；整图精确匹配的配对差异没有显著证据（McNemar p=0.25）。说明局部三元组改善比整图完全修好更明显。

### 5.2 去掉格式失败再看

|子集|文档数|初始 F1|Diagnosis + Gate F1|
|---|---:|---:|---:|
|成功解析的全部输入|215|92.09%|93.53%|
|其中原本不精确|67|74.61%|79.22%|
|其中原本完全正确|148|100.00%|100.00%|
|最初 JSON 失败|10|0.00%|69.91%|

成功解析的错误图也有改善，所以收益并非全来自 JSON 恢复。但 87.99%→92.48% 的整体增益确实包含格式失败的恢复，不能全部称为语义纠错。

这里“自然错误”指由真实模型产生，而不是由人工注入；输入来源仍然是答案字段直接串联的文本，参考仍是 silver。它与自然长文知识图谱的开放域事实错误不同。

依据：[执行路径与机制审计](../exps/paper1_mechanism_audit/report.md)。

## 6. 门控与诊断：完整流程的优势究竟来自哪里

### 6.1 原始门控消融

同一批候选过滤前后：修复率都为 98.00%，整图精确匹配都为 93.33%；F1 从 98.95% 到 99.17%，过度修复从 2.27% 降到 1.67%。共拒绝八个不在参考中的无来源支持三元组。

结论是：门控在这批候选上主要减少额外错误，**没有增加目标缺陷的修复数量**。Direct LLM 同时换了提示，不是一个纯粹的“只去掉预处理”消融。

### 6.2 360 响应的严格匹配上下文实验

60 文档 × 受控／自然两种输入 × Base／Diagnosis／SHACL 三种上下文 = 360 个 Gemma 响应。每个响应再做 raw/gate 配对评分，不为过滤组重新生成。

|上下文，统一过滤后|受控 F1|自然 F1|
|---|---:|---:|
|Base|99.62%|92.52%|
|Diagnosis|98.61%|91.47%|
|SHACL context|99.12%|93.64%|

受控 Diagnosis−Base 为 −1.01 点，95% 区间 [−1.67, −0.38]，探索性 p=0.0082。自然条件 Diagnosis−SHACL 的区间跨零。

这解释了为什么“完整方法赢过旧 Simple”与“诊断没有独立增益”能够同时成立：旧流程比较包含多个变化，匹配实验才更接近单独隔离诊断。SHACL context 是对相关工作上下文设计的任务适配，不是其官方程序的原样复现。

540 条已有 Gemma 响应 × 八种过滤配置 = 4,320 个评分结果。540 由 360 个中文匹配响应与 180 个收据后续修复响应组成。

|关系词汇检查|0.000 pp|0.000 pp|0.000 pp|

## 7. 神经路由与顺序优化器：做完了哪些消融

### 7.1 先区分旧版和 v2

旧路由特征曾读取参考关系是否存在，训练与执行特征也有不一致。旧版接近满分的分类、leave-one-domain-out 和路由成本结果，已撤回作为部署能力证据，不能继续引用来证明泛化。

v2 使用统一的八维公开 profile，网络为 8→32→16，包含修复输出和三个尺度输出，共 884 参数。训练标准化器只在 2,098 条训练行上拟合；验证、测试各 450 行，并按来源文档分组。受控修复／尺度分类达到 100%，但它识别的是注入缺陷的监督标签。

它是**监督训练的路由先验**，不是已通过环境奖励训练的 RL 价值网络。分类准确不等于最终修复 F1。

### 7.2 当前 v2 的 13 组消融

主分析 13 配置 × 450 输入 = 5,850 次；相对均匀先验的敏感性分析再做 5,850 次，总计 11,700 次，全部复用固定候选、零新增 API 请求。

|配置|受控 F1|自然 F1|接受编辑或编辑包：受控／自然|
|---|---:|---:|---:|
|始终开启、均匀先验|84.72%|88.33%|0 / 10|
|始终开启、学习先验|84.72%|87.99%|0 / 10|
|学习先验与触发|84.72%|87.99%|0 / 10|
|去先验惩罚|84.72%|88.33%|0 / 10|
|去动作成本|89.30%|88.13%|68 / 13|
|去密度上界|84.72%|88.33%|0 / 10|
|去质量下界|84.72%|88.33%|0 / 10|
|仅一次迭代|84.72%|88.33%|0 / 10|
|去规则候选|84.72%|88.33%|0 / 9|
|仅规则候选|84.72%|87.99%|0 / 10|
|去局部分数／相应边界|84.72%|87.99%|0 / 0|
|去图分数／相应边界|84.72%|88.33%|0 / 10|
|去来源分数／相应边界|84.72%|87.99%|0 / 10|

这里删除一个质量分数和相应约束，没有删除整个尺度的检测器、候选生成和其他信息。因此它是分数／边界消融，不是完整的 Entity、Graph、Context 三层能力消融。

默认效用中成本和对数先验会使一些编辑的效用不为正。取消成本帮助受控输入，却没有稳定改善自然输入。相对先验零点让学习先验的受控 F1 从 84.72% 到 89.29%，自然 F1 则从 87.99% 到 87.64%；没有据此挑一个测试最好的设置作为默认。

### 7.3 旧轨迹为什么不接受本来有用的候选

对旧版本固定模型编辑子集穷举 2,144 个组合，用参考答案事后选最佳子集：受控 oracle F1 为 99.64%，而当时优化器仅 84.72%；自然 oracle 为 91.73%，优化器为 88.33%。

受控输入中有 86 个图最初未检测到违规，其中 72 个仍不完整，70 个已经有能够改善 F1 的候选；实际候选试探中有 212 次提高参考 F1，却被非正效用拒绝。它区分了“没有候选”和“有候选但没选中”。

这个 oracle 用了参考答案，只是固定候选集合上的事后诊断，不是可部署方法或整个框架的理论上界。它也不能证明 v2 仍具有完全相同的旧停止错误。

### 7.4 跳过模型调用的策略

公开可见违规路由在 450 项 natural/clean 混合流上只路由 6.22% 的输入，但漏掉 63.64% 的不精确图；输出 F1 为 94.46%，始终修复为 95.82%。这是在输入和已存修复结果之间选择的回放，不是又一次在线实测。

**当前结论：选择器组件已被系统检查，但没有证据表明学习先验稳定提高修复质量。** “消融做完”和“每个模块都被证明必要”是两件事。

依据：[v2 完整报告](../exps/paper1_v2_ablation/report_zh.md)、[共享特征修订](../exps/math_revision_20260925/README.md)、[旧选择器诊断](../exps/paper1_offline_diagnostics/report.md)、[版本对应表](paper1_claim_evidence_map_2026-09-28.md)。

## 8. 收据实验：目前最明确的正向外部证据

### 8.1 第一次 60 收据实验

任务为 company、address、date、total 四字段，其中一个缺失地址标注仅在评分中排除，故有 239 个标注字段。

初始、Base raw、Diagnosis raw 都为 79.44% 严格 F1；Base 和 Diagnosis 返回的 60 个图全部未变。加过滤后为 79.15%；SHACL context raw/gate 为 79.86%/79.56%。字段复制为零，因为收据并不是“字段名：值”的串联格式。

过滤拒绝的三个候选全部匹配参考，暴露出源文与标签空白处理不一致造成的误删。49 个字段不匹配中，27 个属于格式，10 个跨度边界，8 个选了另一个来源值，4 个不在规范化来源中。

结论：字段存在、类型合法、文字在原文中，并不保证字段选对。只检查结构很难发现公司名／地址范围选错。这促成了后续的字段定义和证据索引设计。

### 8.2 冻结后在新 60 文档上测试

20 开发收据用于固定设计，随后在另 60 收据上测试。测试标签在预测保存后才获取。各组共享字段定义、编号来源行、初始图与输出要求。

|方法|严格 F1|规范化 F1|整图精确匹配|原正确事实保持|
|---|---:|---:|---:|---:|
|初始抽取|78.33%|79.58%|35.00%|100.00%|
|Simple + Gate|78.75%|80.83%|28.33%|92.50%|
|Evidence Index + Gate|83.51%|86.43%|40.00%|93.06%|
|SHACL context + Gate|78.33%|80.42%|28.33%|93.47%|

预设主比较 Evidence Index−Simple 为 **+4.76 pp**，95% 区间 [2.50, 7.26]，双侧配对随机化 p≈0.0004。规范化后仍有增益，说明差异不全由大小写／空格解释。

但索引不是只改对不改坏：在 52 个原本不精确字段中修好 26 个，同时把 14 个原本精确的字段改成不精确。Simple 对应为修好 16、改坏 15。索引丢失的 14 个精确匹配中有 10 个仍保留相同金额，只改变显示格式；金额数值准确率从初始 58/60 到索引 59/60。这正是需要区分精确指标和语义判断的原因。

本轮测试包含 60 次初始抽取和 180 次修复，共240次实际请求；过滤前后复用同一响应。Simple、Index、SHACL 的平均修复请求耗时约7.91、7.88、8.11秒，平均输入token为1,784、2,153、3,404，说明同调用预算并不意味着同token预算。

这一轮过滤仅拒绝一个不匹配参考的地址拼接候选，对索引 F1 的贡献约 0.18 点。主要正向差异来自生成上下文，而不是过滤本身。

### 8.3 索引定位的事后分析

240 参考字段中：188 在索引内，36 在索引外但能在来源匹配，16 无法按固定规则匹配来源。在 188 个命中字段中，Simple 正确 163 个、Index 正确 174 个，净增 11；其中地址净增 8，公司名净增 3。索引外组都是 26 个正确，无净增。

这与“证据定位有帮助”一致，但只是关联分层：不能用参考值事后位于索引内，替代在线随机上下文对照或人工证明。

### 8.4 索引是否比更简单的上下文更好

后续 360 个同期响应，在复用的 60 收据上比较六组：

|条件，统一过滤后|F1|
|---|---:|
|Simple|79.17%|
|完整索引|83.51%|
|仅锚点|83.51%|
|随机索引|81.67%|
|Simple，无字段定义|80.83%|
|完整索引，无字段定义|74.70%|

完整索引−Simple 为 +4.35 点，但五项 Holm 校正后 p=0.0652。完整索引−随机索引为 +1.85 点，区间跨零；完整索引与仅锚点均值相同。去掉字段定义使完整索引下降 8.81 点，校正 p=0.0060。

因此，当前支持“字段定义与索引上下文的组合有用”，尚不能证明邻近行必要或定向索引可靠胜过随机附加上下文。随机索引仅近似匹配字符长度，不是严格等 token。

首次后续测试的 +4.76 与同期控制的 +4.35 不是同一批模型响应，且检验家族不同，不构成算术矛盾。

依据：[首次收据](../exps/paper1_external_receipts/report.md)、[后续独立测试](../exps/paper1_receipt_followup/test/report.md)、[字段转移解释](../paper1/sections/receipt_followup.tex)、[索引定位](../exps/paper1_index_localization/report_zh.md)。

## 9. 有旧图的修复是否胜过从头重新抽取

### 9.1 60 收据、四组、240 请求

有／无旧图 × 有／无索引。240 次 Gemma 请求全部 HTTP 成功，但都返回 Markdown JSON 围栏，冻结严格解析器全部判失败。**预定严格主分析各组 F1 都为零，无法回答语义优势。** 这不是模型没有生成内容，而是输出与解析契约不一致。

随后统一剥离外围代码围栏，作为明确标注的事后兼容性分析。过滤后的索引修复 F1 为 83.93%，索引重抽取为 61.05%，差 22.88 点。

进一步发现索引重抽取有 28/60 图使用错误文档 ID，修复组没有。统一代码赋予已知文档 ID 后，重抽取为 74.86%，修复仍为 83.93%，差距缩至 9.07 点，95% 区间 [5.22, 13.10]。

因此完整 22.88 点不能全部解释为字段修复机制的收益；较小差距仍来自事后分析和已用过的文档，不能写成预注册的新任务结果。初始图历史构建成本也不能漏计后宣称修复天然更便宜。

依据：[240 请求完整报告](../exps/paper1_online_recovery/reextraction/report_zh.md)。

### 9.2 CUAD：在新任务上预先解决解析与 ID 问题

固定五字段：合同名、签署日期、生效日期、到期日期或初始期限、管辖法律。全文不超过 40,000 字符，字段至多一个不同的空白规范化参考值；符合条件的官方测试合同只有 56 份，全部纳入，不放宽条件凑 60。

四组为初始抽取、Simple repair、Indexed repair、Indexed re-extraction。修复组接收同一初始图；索引组加入固定字段锚点窗口，仍保留全文。模型、字段定义和 4,000-token 输出预算相同。代码围栏兼容、文档 ID、解析和统计在正式采集前固定。

|组别|测试 F1|丢失的初始正确事实|新增不匹配参考事实|失败输出|实际请求|
|---|---:|---:|---:|---:|---:|
|初始抽取|46.76%|0|0|0|59|
|Simple repair|43.35%|7|2|3|71|
|Indexed repair|44.84%|5|12|2|69|
|Indexed re-extraction|44.12%|8|32|2|71|

20 个开发合同共 80 输出、84 请求；测试 56×4=224 输出、270 请求。测试中的七个运输失败保留为空图，没有挑选重跑。恢复后仅补齐八个此前未执行项。

唯一主比较是 Indexed repair−Indexed re-extraction：**+0.72 pp，95% 区间 [−4.80, 6.48]，p=0.8101。** 两组均值还低于初始抽取，但本次主检验不是“各修复组是否显著低于初始抽取”，不能对该观察额外下显著性结论。

初始抽取行的“新增错误=0”表示相对于它自身没有新增，不表示初始图无错误。其他组“新增错误”也只是新出现的不匹配参考事实，不是输出全部错误的总数。

此测试未证明保留旧图能带来可靠收益，也没有证明两者等效。其任务是较短、单值兼容合同的字段跨度匹配，不是完整 CUAD 问答任务，不能直接和官方 QA 排名比较。

依据：[CUAD 开发报告](../exps/paper1_cuad/dev_report.md)、[测试报告](../exps/paper1_cuad/test_report.md)、[机器结果](../exps/paper1_cuad/test_results.json)。

## 10. 跨模型、规模与辅助验证

### 10.1 同一 60 受控文档上的跨模型流程比较

|模型|Direct 修复率／F1|Simple 修复率／F1|Diagnosis + Gate 修复率／F1|
|---|---|---|---|
|历史 Claude Haiku|95.8% / 97.0%|95.8% / 96.6%|97.5% / 99.1%|
|Gemma|95.8% / 98.8%|96.7% / 98.4%|98.3% / 99.0%|

完整流程在两个模型上修复率都最高，但 Gemma 上与简单流程的差距较小。这是同一任务的小样本跨模型检查，不能替代新领域、未见关系和自然事实错误泛化；也没有隔离各组件的跨模型贡献。

### 10.2 诊断批量规模

|三元组数|独立文档数|全量诊断中位耗时|单文档局部更新|新增 Python 分配峰值|
|---|---:|---:|---:|---:|

### 10.3 辅助评分与外部抽取

Gemma 对 180 个来源—三元组对的来源支持评分，与精确参考有效性相关：Pearson 0.794、Spearman 0.807。50 项重复五次均值相同，是模型评分重复性证据，不是独立人工一致性。

45 个 TNEWS 文档中，当前抽取路径类别准确率 0.556，Neo4j `LLMGraphTransformer` 核心为 0.533，配对 p=1.00。TNEWS 没有金标准三元组，所以该实验不能证明图谱事实修复优于 Neo4j 或通用 agent。

## 11. 人工实验、成本与复现的准确状态

人工包已经准备，每位标注者分别处理 200 条输入差异和 200 条实际编辑，两位独立填写，再计算裁决前一致性和分歧裁决。当前没有真实结果回收入库，不能填入人工准确率、kappa 或人为假定分歧已经解决。

成本要分三种：真实生成请求；同一响应离线过滤／回放；利用存储结果估算的调用策略。raw/gate 一对不等于两次请求，11,700 次回放也不是 11,700 次模型调用。许多耗时包含限速等待和重试，不能直接解释成纯模型推理延迟。CUAD 的修复请求成本需另加初始建图成本才能比较完整工作流。

源码、图、模型响应与失败记录有各自入口。论文编译、60 项跨项目实现测试及历史文件哈希检查证明的是软件与材料可核查，不能作为额外样本添加到修复精度分母。

人工入口：[说明与交付包](../exps/paper1_human_review/README.md)。

## 12. 综合判断：哪些结论已经成立，哪些仍不成立

|判断|当前证据|
|---|---|
|单次来源约束生成与过滤能改善特定中文字段图|支持；受控与真实抽取输出均有配对结果|
|中文主任务必须依赖复杂模型修复|不支持；字段复制达到 100%|
|门控能拦截一些可定位的错误候选|支持；有同响应、逐检查和拒绝记录|
|门控在所有场景都不会误删|不支持；首次收据误删三个参考候选|
|诊断上下文具有稳定独立收益|未证明；多项匹配结果为负或校正后不显著|
|神经路由／顺序优化器稳定提高端到端 F1|未证明；v2 系统消融没有显示稳定增益|
|字段证据索引在新收据上有作用|支持；冻结新测试 +4.76 pp，规范化后仍有差异|
|完整索引可靠胜过仅锚点或随机上下文|未证明|
|旧图修复在新合同任务上优于重新抽取|未证明；主比较 +0.72 pp，区间跨零|
|完整三尺度、跨文档语义及因果链能力已验证|没有直接实验支持|
|真实系统编辑已通过双人语义核验|尚未完成|

整篇论文当前最有依据的认识是：**修复收益取决于来源格式、字段定义、候选质量以及约束与任务是否匹配。完整流程可以有效，但复杂模块的额外价值需要逐项证明。** 收据证据定位提供了正向结果；更强简单基线、严格组件对照和合同测试同时划定了它的适用范围。
