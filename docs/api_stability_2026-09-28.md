## 测试方法与负载

- 共 24 次请求，每个模型 12 次，不自动重试，不筛选重跑失败样本。
- 逐个短请求：每个模型 4 次，检查带独立 case 标识的 JSON 与简单算术结果。
- 低并发短请求：每个模型 4 次，最多两个工作线程，全局启动间隔至少 3 秒。
- 低并发长文档：每个模型 4 次，约 24,499 字符的合成输入；成功响应报告约 8,186–8,221 个输入 tokens。要求返回 20 个字段三元组，检查字段值、关系、文档节点及数量。
- 温度 0；短任务完成上限 128 tokens，长任务上限 4,000 tokens。实际长输出约数百 tokens，没有验证接近 4,000 tokens 的持续生成。
- 网络操作超时设置为 60 秒。该设置不是严格端到端截止时间；两次超时的墙钟时间为 65.081、60.315 秒。不能据此断言更长等待时限也会失败。
- 请求时间从完成本地限速等待后开始计算，包含网络与服务等待；不包含限速队列时间，也不等同于纯模型推理时间。

22 条成功响应共报告 50,044 输入 tokens、4,224 输出 tokens。超时请求的服务端执行状态和 usage 未知，以上不是完整计费估算。

## 需要区分的两类问题

### Gemma：连接正常，但输出仍需按正式协议评分

两次长任务返回了可解析的 20 个三元组，字段值与关系正确，但所有 head 都写成通用字符串 `document`，没有使用输入指定的文档节点。另两次完全符合预期。

这是合成测试下的输出内容问题，不是连接超时。正式实验应保存原始响应，按冻结解析／过滤／评分规则处理；不能为提高分数修改响应或对内容错误选择性重试。

### Qwen：长请求延迟及模型标识需单独核对

两个长请求分别在 40.199 和 57.971 秒完成；另外两个超时。短请求全部返回，但耗时也存在波动。

请求名为 `Qwen3.8-27B-no-thinking`，10 次成功响应的模型字段均为 `Qwen/Qwen3.8-27B`。这可能是网关的统一别名，不能仅凭响应字段确认 no-thinking 配置实际生效。未请求其他模型来替代该检查。
