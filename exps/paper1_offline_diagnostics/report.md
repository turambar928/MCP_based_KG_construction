# Paper 1：服务维护期间的离线机制分析

不调用 API，不下载模型，不修改参数，不使用正在进行的人工标注。分析对象是已保存的 450 个输入和候选输出；并非新的测试集。

## 结论

1. **停止条件漏掉缺失字段。** 受控输入中 86 个图起始时没有被检测出违规，其中 72 个仍不完整；70 个已有能改善 F1 的候选组合，却没有进入选择。自然输入对应为 198 个无违规、50 个不精确、8 个存在可改善候选。
2. **候选评分压制正确修改。** 在受控输入实际进入评分的试探中，有 212 次提高参考 F1，却因效用不为正而被拒绝；自然输入为 1 次。计数单位为候选试探，不能当作独立文档。
3. **放宽成本不是通用修复。** 相对 uniform 基准，受控文档 67 个改善、0 个变差；自然文档 0 个改善、3 个变差。自然数据的 148 个预处理后完全正确输入均未被伤害；损失集中在原本有错的图。
4. **零增益已检查到逐文档输出。** 路由先验、触发器和多项约束开关的零增益不是正负变化相互抵消；完整变更计数见 `variant_summary.csv`。部分其他设置则有输出改变但 F1 不变，因此没有只靠平均值判断。

## 固定候选的参考辅助上界

穷举 2144 个模型候选编辑子集。每个文档保留原输入或选取已有编辑，不生成新事实；用运行时同一套编辑操作执行，保留重复添加语义。参考标签只用来事后挑选最优子集。

|输入|预处理 F1|顺序优化 F1|固定候选 oracle F1|
|---|---:|---:|---:|
|controlled|0.8472|0.8472|0.9964|
|natural|0.8799|0.8833|0.9173|

该上界仅适用于这里固定的模型编辑子集，不是生产方法、不是整体框架的理论上界，也不覆盖过滤器、规则候选和重新生成的输出。自然数据仍用原有 silver 参考。
