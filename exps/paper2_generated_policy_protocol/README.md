# Paper2 生成规则参与学习调度：下一轮冻结设计

本目录完成路线图 P2-O2 的接口与实验设计。**尚未实现新训练环境，也没有生成规则 RL 的效果结果。**论文仍保留 RL 图谱—规则协同优化与双策略生成主线；本协议针对目前缺失的连接实验，不替换已有八动作实验。

`protocol.json` 明确每次获取单位、公开观测、四个动作、奖励公式、预算、分组划分、基线、统计方法与验收测试。每次获取是一份来源文档的一次生成响应，不是整个归档库。每份响应中允许多条规则；解析失败或没有候选也消耗一个获取预算。缓存重放的实际 API 调用始终为零，不能写成一次真实在线生成。

14 维观测与旧环境碰巧同维不表示兼容：含义及四动作输出均不同，必须新训练。每个候选保留 strategy、source_document_id、packet_id、response_sha256、prompt_sha256、model、attempts、usage、时间和被拒原因；重复规则合并身份但保留多来源。

奖励只读取公开图与已获取规则。它是约束与覆盖代理，不是事实正确率。新增规则可能揭示更多违规、短期降低奖励，因此保留立即停止与固定获取流程作为控制，检查奖励是否抑制有益获取。不能先观察测试结果再改奖励，也不能把规则数量增加直接作为语义质量提升。

正式开始前需要：可信类型和关系映射、同源双策略生成响应、适用规则的独立核验、来源分组划分以及真实语义参考。当前类型审计没有恢复可用于原始三图的类型；既有 RuleTest-94 的四种调度终态一致。因此现阶段不启动没有有效决策差异的训练。

协议列出的 12 类验收测试是**待实现环境必须通过的测试清单**，不是宣称全部已执行。当前已有四命令桥接器的测试继续保留；不能拿它们替代新奖励／队列环境的测试。

数据就绪后，先物化 packet 清单及 source-document 划分、封存标签，再实现并测试环境；冻结实现、数据哈希和模型配置后统一运行全部预定策略。记录所有场景（包括策略相同的场景），不筛选只支持 RL 的案例。
