# Paper1 回收结果：协调员裁决说明

两份 JSON 均通过原校验：每人 400 条，D 输入差异 200 条、E 实际编辑 200 条。原始标签和理由完整保留。独立标注已完成，最终裁决尚未完成。

本包仅供协调员／裁决者使用，不应当作为两位标注者重新独立填写的模板。没有公开方法身份。已有一致性必须保留，不通过让双方改成一样来提高一致率。

## 需要做什么

1. 阅读原包的标签说明，尤其是 D 的建议操作与 E 的实际输出的区别。
2. 查看 `争议索引.csv`，定位 154 个争议条目（D 76、E 78），共 214 个标签判断有分歧。
3. 在 `merged/D_adjudication.csv` 和 `merged/E_adjudication.csv` 中阅读对应的原文、schema、输入图谱、输出图谱、指定操作和两人的理由。
4. **只编辑最后三个裁决列**：`adjudicated_is_error`、`adjudicated_repair_acceptable`、`adjudication_notes`。空白标签填 `0`、`1` 或 `U`，填写理由；无法确定保留 U。不要改原始独立标签、备注、ID 或上下文。
5. 一致标签已由原合并脚本复制到裁决列。若核查后要改变一致标签，也只改裁决列并说明理由。不要删除非争议条目；评分需要完整的两张 200 行表。
6. 将两个完整 CSV 和原 `return_manifest.json` 一并交回，保留副本。可用支持 UTF-8 的表格软件编辑，但不要把长文本截断；不要只交争议索引。

## 当前最需要统一的解释

以下内容重申原说明，不替条目给答案，不增加新的评判标准：

- `is_error` 与 `repair_acceptable` 独立。事实本来没有错，但等价替换保留正确信息，可能是 0/1。
- D 的 add 是指定的增加建议，不能自动假定还会执行未显示的删除或合并。检查输入是否已有等价事实，以及增加是否产生同字段重复。
- E 需要结合完整输出图谱判断。不能只凭新增值在原文中出现就判断操作可接受；也不能不看完整输出，自动把所有 add 当作产生重复。
- 原任务按每字段至多一个值定义；同时应区分真正多值、冗余副本和一次完整的等价替换。对责任事项、法规长文本等字段，须核对完整表达和具体操作。
- 不能把另一处图谱错误算到当前指定操作头上。存在歧义时写清依据并保留 U。

独立文件中 D 的操作可接受性有 76 条 A=1/B=0；E 有 63 条 A=1/B=0，另有反向和 U 分歧。若干理由提示“等价写法规范化”与“新增重复／多值”的解释不同，须逐条依据完整上下文裁决，不能整批采用 A 或 B 的标签。

## 完成后如何统计

保留本包 `merged/` 结构，在原仓库根目录运行：

```bash
/tmp/kgbench-local-venv/bin/python exps/paper1_human_review/process_returns.py score --folder /你的路径/merged
```

原评分器会检查独立标签与上下文哈希，拒绝缺失裁决标签。助手本次没有运行最终评分，也没有填任何分歧标签。

论文还需如实记录标注者背景、是否使用练习、独立流程，以及最终由谁裁决（第三人还是双方讨论）。这些不能仅从 JSON 确定。即使裁决完成，也只能报告抽样差异和操作的人工结果，不能当成整图人工 F1；“纯格式变化”等细分类仍需另外的真人判断。
