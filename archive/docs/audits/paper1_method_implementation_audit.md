# Paper 1 method–execution audit

Updated: 2026-09-21. This audit supersedes the 2026-09-17 assertion that the
headline benchmark exercised the full sequential optimizer.

## Actual inference path

The archived headline results were generated by
`exps/paper1_repair_benchmark/run_benchmark.py:ours_method`:

1. `rule_only` normalizes structural defects.
2. `tool_report` supplies diagnostic context to a single LLM call.
3. `constrain_output` filters generated triples.

It does **not** call `MultiScaleConstraintOptimizer.optimize_and_apply`, its
learned prior, trial-state profile, restoration constraints, utility function,
or multi-step planner. The paper now describes the executed source-grounded
pipeline; the phrase "Full System" has been replaced by "Diagnosis + Gate".
The older names in immutable prediction files remain historical identifiers.

## What the new audit executed

`exps/paper1_mechanism_audit/replay_optimizer.py` invokes the actual optimizer on
225 controlled and 225 naturally extracted inputs, with the same archived
candidate responses. Per-relation input/proposal differences form atomic edit
bundles. Confidence is 0.7, all runtime costs and thresholds are defaults, and
the horizon is 12. No parameter was selected by its held-out repair result.
Both learned routing and always-on uniform routing are evaluated. A source
matching bug was corrected by normalizing whitespace on both source and tail;
all 900 outcomes were rerun. The pre-fix 900 outcomes are also retained, and
the controlled conclusion is unchanged. Natural F1 is 0.8844 before and 0.8833
after this bug fix; neither result is substituted with the better pipeline.

The 900 saved outcomes contain initial/final profiles, every evaluated trial
graph, feasibility/utility decisions, accepted actions, and stopping reasons.
The runtime source SHA-256 is included with every record.

- Controlled: both variants accept zero additional actions; repair stays at
  0.3200 and triple F1 at 0.8472, the structural-preprocessing result.
- Natural: both variants reach 0.8833 F1 and 0.6578 exact match.
- The archived pipeline instead reaches 0.9800 repair/0.9917 F1 controlled and
  0.9248 F1 natural. Those values cannot be attributed to the optimizer.

This is a negative result about this finite-candidate adapter and runtime
configuration, not a proof that all sequential graph optimizers fail.

## Reference leakage and incompatible profiles

The previous `exps/decision_network/build_from_repair_benchmark.py:graph_features`
constructs `expected_relations` from `case['clean_triples']`. Its `S_iso` measures
reference-field coverage. The runtime optimizer's `S_iso` instead measures
non-isolated nodes. The two use different duplicate, logical, and density
calculations as well. Hence the old router and leave-one-domain-out scores do
not validate the deployed runtime feature map or gold-free natural routing.

Those datasets/results are retained as historical artifacts, explicitly
withdrawn as deployment evidence. The active method has no learned router.
New inference accepts a `PublicInput` containing only source, declared head,
allowed predicates, and input triples. The reference is accessed by the scorer.
The required head is treated as supplied task metadata; its extraction from the
legacy reference storage layout is disclosed. Tests perturb reference tails,
relation presence, and defect labels without changing inference inputs.

The replacement gold-free violation-policy replay routes 6.22% of a 450-item
natural/clean stream but misses 63.64% of imperfect graphs. Its F1 is 0.9446 vs
0.9582 for always calling repair. It is a cached-output replay, not online
end-to-end latency. Main quality results always call the model.

## Current mathematical contract

The active method defines a declared head predicate H, allowed-relation
predicate R, and literal source-support predicate S. Eligible generated triples
satisfy HRS=1. At most one eligible triple per relation is retained, with a
first-in-generation-order tie-break. This selects a maximum-cardinality subset
of the eligible candidates under independent per-relation capacity-one groups.
It does not maximize semantic accuracy, recover facts absent from all
candidates, guarantee preservation of the input, or perform reinforcement
learning. Literal occurrence is necessary under the extractive contract but
insufficient for relation-level entailment.

The seven-algorithm mathematical analysis in the older revision summary remains
a history of the separate runtime. It is not a specification of the current
headline experiment. No RL training is claimed.

## New mechanism evidence and human review

The Gemma-only matched experiment varies base/diagnostic/SHACL context under one
system prompt and completion cap, and compares raw/gated outputs on the same
response. `BASELINE_ADAPTATION.md` documents how the SHACL arm follows Lin et al.
(2025), including all deviations. It is not an official implementation claim.

The natural-error benchmark is separately scored on valid and malformed JSON.
Independent human labels are still required for the frozen input-discrepancy
sample and system-edit audit. Agreement is calculated before adjudication,
preserving uncertain labels. No model output is described as a human label.


## Source-format baseline: unresolved submission limitation

A further audit of `build_benchmark.record_to_graph` shows that source evidence
is serialized from the same field values used to define the reference triples.
The gold-free `source_field_baseline.py` reads only the source and declared
schema. It obtains 1.0000 repair/F1/exact match on controlled inputs and 1.0000
F1/exact match on natural inputs, with zero API calls. This result is included
in the manuscript and primary figure; it is not suppressed as an inconvenient
baseline. Therefore neither current protocol establishes superiority of LLM
repair over direct source reconstruction. Independent, unstructured-source
annotations are needed before treating the draft as ready for DMKD submission.
