更新：2026-10-04。版本：`independent-rule-feasibility-20261004-v1`。

**本轮完成了协议、样本及请求冻结、采集与分析脚本、离线测试；实际模型请求为 0，训练为 0。** 论文继续保留 RL 图谱—规则协同优化与双策略生成主线。本文件不参与 Overleaf 编译，不需要替换已经调整好的模板或正文。

## 1. 这次要回答什么

下一步先验证三个前提：生成规则能否带来安全的参考事实恢复；删除与扩增两种生成策略是否提供有效互补；不同获取与修复安排是否留下值得研究的调度空间。只有这些前提成立，才值得设计生成规则环境中的学习实验。

原八动作 RL 实验已经完成。这次针对的是**实际生成规则进入四动作环境**的后续验证，两者不能混成同一组训练结果。

旧源证据协议已完成两轮并停止。第二轮 F1 为 95.69%，移除 7/31 个注入项，没有丢失正确参考事实，但移除全部来自类型规则；离线穷举也没有发现超过简单流程的最终 F1 空间。旧结果、编译器和正式训练阻断状态全部保留。

本协议是吸收旧失败经验后，单独登记的新开发研究：修订输出格式说明，并使用未参加既有生成试验的开发文档。**它不是旧两轮协议的“第三轮”，也不是独立的确认性测试。** 样本和提示同时变化，因此即使新结果更好，也不能把差异单独归因于提示格式修改。

## 2. 样本、输入和预算

|项目|冻结安排|
|---|---|
|数据来源|既有 DocRED 划分中的 dev；不访问 train/test 文本或参考标签|
|排除条件|排除旧 typed pilot、两轮 source pilot 的成员以及旧响应日志中出现过的文档|
|选择方式|按原 dev 配对顺序，取前 10 个两个成员都未用过的文档对；不按内容或结果挑选|
|实际选择|20 文档、10 个 episode，与既有生成试验的 30 个不同文档无重叠|
|图构造|每对第一篇使用参考关系图，第二篇加入约参考关系数 20% 的随机替换候选；沿用 v2 构造与种子|
|策略|每篇分别执行 deletion 和 augmentation，两个策略都可输出 type/source 规则|
|唯一模型|`google/gemma-4-26B-A4B-it`；没有模型回退，不请求 GPT、Claude 或其他模型|
|生成参数|temperature 0、max_tokens 4000、最多 20 条规则、最多 3 条补充语句|
|规模|40 个计划输出；每任务最多 2 次请求尝试，整批最多 80 个派发意图|
|执行|单工作进程，请求前间隔 3 秒；绕过环境代理、不跟随重定向|

目前恰好有 10 个完整 dev 对满足排除条件，已全部冻结；没有剩余合格完整对可用于结果不好后的替换。部分其他文档本身未使用，但其配对成员已使用，故整对排除。

模型可见原文、给定实体和类型、关系词表、当前图记录及策略对应的文本变换。参考关系和注入身份只进入单独评分文件，不传给生成器、策略或轨迹枚举器。不过，当前输入图本身由参考图构造，因此这是**受控参考恢复任务**，不是自然错误测试；DocRED 未标出的关系也不能自动被视为现实中的错误事实。

冻结记录见 `../exps/paper2_rule_feasibility_20261004/membership.json`、`protocol.json`、`manifest.json`。原文、请求及评分标签留在该目录被 Git 忽略的 `local/` 中；公开 manifest 保存对应哈希。

## 3. 输出与采集规则

格式约定已在采集前固定：一个 JSON 对象，可带一层完整 Markdown JSON 围栏；拒绝重复键、非有限数值、额外字段、非法枚举及超出数量上限的响应。整个对象不符合 schema 时，整包记失败，不保留其中看似有效的部分。

- 类型规则分别使用具体的 `allowed` 或 `forbidden` 值，不把两个值拼成示例字符串。
- 来源规则分别使用 `supported`、`contradicted` 或 `insufficient`。前两者要求原文逐字引用；不充分证据使用空引用并弃权。
- 原有编译器继续检查词表、记录归属及引用位置；补充假设句不能充当来源证据。
- 引用存在只证明可追溯，不证明引用支持规则语义。人工语义判断保持待完成，不由格式合格率代替。
- 只接收返回模型完全匹配且 `finish_reason=stop` 的完整响应。截断和解析错误保存为失败，不追加“修复 JSON”的模型调用。

采集器在网络请求前持久化派发意图，完成后记录状态、耗时、usage 和响应。只对运输异常及 HTTP 429/500/502/503/504 重试。连续两个任务最终出现运输或响应协议错误时停止；模型不匹配时立即停止。已完成的失败任务也不重跑。

如果进程在请求途中中断，恢复时将未决请求记为 `interrupted`，单独报告未知送达数，**不自动重发**。日志尾部损坏则直接报错，保留文件供核查。不能把未知送达算成“肯定没有请求”，也不能删日志后重跑。

## 4. 离线比较与成本口径

每个 episode 包含 4 个冻结响应包，环境动作仍为获取 deletion、获取 augmentation、repair、stop，最多 10 步，折扣率 0.95。沿用已修正奖励的环境，不改旧代码。

固定比较如下：

1. 直接停止。
2. 先取得两种策略全部包，再修复。
3. deletion 优先，出现可修复项就立即修复。
4. augmentation 优先，全部取得后修复。
5. augmentation 优先，出现可修复项就立即修复。
6. 仅 deletion。
7. 仅 augmentation。
8. 均匀随机可行动作，包含 stop，种子固定。

另外枚举所有可行路径，检查每条固定轨迹的最终记录、F1、参考保留率、移除数、获取包数和折扣回报是否与枚举完全一致。

报告按 10 个文档对计算平均 F1 和参考保留率，同时列出正确参考丢失数、注入项移除数、来源规则必要移除数及各策略独有移除数。固定策略相对 stop 的 F1 差异用文档对为单位作 10,000 次 bootstrap，固定种子 20261004；这些区间用于开发诊断，不作确认性显著性主张。

**获取包数与实际 API 成本分列。** 这次为比较全部策略而预先采集 40 包，离线轨迹只是在已有包中选择。轨迹少取两包不等于已经实测省了两次在线请求。真实成本来自日志中的请求尝试、失败、重试、未知送达、usage 和耗时。

## 5. 进入下一阶段的四个数值条件

所有 40 个任务必须先终结，包括失败和中断；然后一次性分析，不边看结果边调提示、换文档或选策略。

|条件|冻结标准|作用|
|---|---|---|
|格式可用|至少 36/40 个响应满足完整 schema|排除接口仍不稳定的情况；空规则也算格式合格，所以必须同时满足后三项|
|有效参考恢复|**同一个**确定性非 stop 策略平均 F1 高于 stop、平均参考保留率至少 99%，且至少 2 个 episode 出现来源规则必要的注入项移除|避免分别挑不同策略的最佳指标拼成一次成功|
|双策略互补|仅 deletion 与仅 augmentation 各自至少移除 1 个另一策略没有移除的注入项，且两种单策略流程均无正确参考丢失|验证两个生成策略各有安全的独有贡献|
|调度空间|安全可行路径的逐 episode 最佳 F1 均值比最强确定性固定策略高至少 0.5 个百分点；**或**同等/更好质量且不增加参考丢失的安全路径平均少取至少 1 包，并在至少 2 个 episode 中各少取至少 1 包|先判断是否存在值得学习的质量或成本空间|

“来源规则必要”在实际编辑之前的同一状态计算：去掉来源矛盾规则后，该记录不再被判违规。如果类型规则自己就会删除它，不把它计作来源规则的独立贡献。这是局部机制诊断，不是来源规则整体效果的因果估计。

安全路径要求该 episode 参考保留率至少 99%。最强固定策略按平均 F1、平均保留率、平均获取包数依次比较。逐 episode 最优路径使用评分参考，是**事后 oracle 诊断**；其质量和节省量不代表可部署策略已经达到。

四项都通过只表示“可以单独设计正式实验”，不自动启动训练，也不解除旧正式 runner 的阻断。下一份正式协议仍须先冻结训练来源、预算、种子、DDQN/DQN 与强启发式和同预算自适应基线、未见测试及主要指标。人工语义核验仍由作者安排。

若任一项未通过，保存整批失败与负结果，停止扩大。本研究不预设第二个调参轮次，也不通过更名继续用相同文档反复试到通过。
