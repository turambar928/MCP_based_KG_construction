\section{Introduction}
\label{sec:introduction}

Knowledge graphs extracted from documents often contain missing fields,
incorrect values, duplicate triples, and schema violations. These errors
reduce the quality of information retrieval and decision support
\citep{ref_ji2021,ref_paulheim2017}. In many extraction workflows, the source
text remains available and provides evidence for checking and repairing the
graph.

Schema checks and language models serve different roles in this process.
A schema check can identify an invalid relation or duplicate value. A language
model can read the source and recover a missing field, but it can also change
a correct value or add an unsupported fact. Work on KG quality and SHACL
validation provides tools for checking graph constraints
\citep{ref_zaveri2016,ref_kontokostas2014,ref_shacl2017}. Lin et al.\ combine
constraints and graph context in LLM repair prompts \citep{ref_lin2025}.
These approaches motivate a practical question: how much do diagnostic context
and output validation each contribute to source-based repair?

We study document-field graphs with a declared document node, a set of allowed
relations, and at most one value per relation. Our pipeline first normalizes
the input graph. A language model then proposes a complete graph using the
source text and an optional diagnostic report. A deterministic filter checks
each proposed triple for a valid head, an allowed relation, a value present in
the source, and compliance with the one-value-per-field rule. It records a
reason for each rejected triple.

The evaluation separates generation from validation. We compare base,
diagnostic, and SHACL contexts under the same instructions and completion
budget. Each response is scored before and after filtering. This design
measures the effect of context on generation and the effect of filtering on a
fixed set of candidates. We also compare a sequential selector and measure the
cost of updating diagnostic reports.

We use controlled defects and actual extraction outputs from three Chinese
record collections. Their source text lists the target fields explicitly,
and a field-copy parser recovers all reference graphs. We therefore add an
external test on SROIE receipt transcripts, whose text and human field labels
are stored separately. The two settings let us compare behavior on serialized
records and independently annotated document text.
An error analysis then guides a small follow-up: shared field definitions
and a deterministic index of source evidence lines. We evaluate this variant
on a separate development set and freeze it before a new document test.

The paper provides three main results:
\begin{itemize}
    \item A source-based candidate-validation procedure with explicit input
    requirements, field constraints, and rejection logs.
    \item A repair evaluation covering controlled defects, model extraction
    errors, and external receipt text, with measures of fact recovery,
    preservation, and harmful edits.
    \item A matched comparison of diagnostic context, field-evidence lines, SHACL context, and
    candidate filtering, supported by per-document predictions, statistical
    comparisons, and execution traces.
\end{itemize}
