\section{Introduction}
\label{sec:introduction}

Knowledge graphs extracted from documents can contain missing fields,
incorrect values, duplicate triples, and schema violations. Such errors affect
applications that rely on structured evidence, including information retrieval
and decision support \citep{ref_ji2021,ref_paulheim2017}. The source document
remains available in many extraction workflows, making it possible to inspect
both the proposed graph and its textual evidence during repair.

Different forms of evidence answer different questions. Schema validation can
reject an illegal predicate, but cannot recover an omitted value from text.
A language model can propose that value, but may also replace a valid field or
introduce an unsupported assertion. Existing quality frameworks and SHACL-based
validation expose these complementary concerns
\citep{ref_zaveri2016,ref_kontokostas2014,ref_shacl2017}. Lin et al.\ already
show that relevant constraints and graph context can improve LLM-based repair
\citep{ref_lin2025}. Consequently, the presence of a diagnostic prompt or a
constraint checker alone is not sufficient evidence of a new repair mechanism.

We study a restricted, operational setting: each source document has a small
field-level graph with a declared document node, a permitted relation
vocabulary, and at most one value per relation. We evaluate deterministic
structural normalization, diagnostic context in a source-grounded model call,
and explicit filtering of candidate triples. The filter rejects candidates
with invalid heads or predicates, absent source spans, duplicate content, or
relation-cardinality conflicts. These predicates are auditable, but literal
source support does not establish relation-level semantic correctness.

Our central empirical question is whether diagnostic context and candidate
validation improve repair beyond a strong one-call pipeline with the same
preprocessing. We first evaluate 450 controlled defects in 225 held-out
document graphs, then examine 225 fresh extraction outputs with naturally
occurring discrepancies against structured source records. A new matched
experiment fixes model instructions and completion budget, varies only the
added context, and evaluates each response both before and after filtering.
A SHACL-context arm adapts the prompting structure of Lin et al.\ to the same
task \citep{ref_lin2025}.

The distinction between a proposed architecture and an executed method is
critical to this comparison. The repository also contains a sequential
trial-state optimizer and a learned router. We execute the optimizer on frozen
candidate responses and inspect the input features used by the router.
The resulting evidence does not justify attributing the pipeline's gains to
neural routing or sequential utility maximization. We report that negative
finding and restrict the main method to the executed one-call pipeline.

A source-format audit also finds that the benchmark evidence serializes the
reference fields explicitly. A deterministic field-copy baseline reaches
perfect recovery without model calls. We include this baseline and therefore
do not claim that the controlled or natural-output results establish a need
for LLM repair on these records. Independent unstructured-source evaluation
remains an unresolved requirement.

The contributions are:
\begin{itemize}
    \item An explicit source-grounded candidate-validation procedure for
    document-field graphs, with a reproducible input contract, deterministic
    rejection reasons, and clearly delimited guarantees.
    \item A controlled and natural-output evaluation that measures recovery,
    preservation, harmful edits, and exact graph match, including a separate
    analysis of malformed extraction outputs and valid-JSON factual errors.
    \item A mechanism audit using shared prompts, response-paired filtering,
    a literature-informed SHACL-context baseline, and actual execution traces
    for the earlier sequential optimizer. This audit identifies which
    architectural claims the observed results do and do not support.
\end{itemize}
