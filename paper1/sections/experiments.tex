\section{Evaluation}
\label{sec:eval}
\label{sec:experiments}

We evaluate document-level KG repair under two complementary protocols. A
controlled paired benchmark provides exact defect provenance and supports
per-defect statistical tests. A separate extraction benchmark contains errors
that arise from a real text-to-graph call rather than from an injection
procedure. We then audit the execution path and isolate diagnostic-context and filtering effects with matched model calls.

\subsection{Experimental Protocol}
\label{sec:eval:setup}

\paragraph{Source records and controlled pairs.}
The source corpora contain 4,728 government-affairs records from the Shaanxi
Provincial Government website, 1,000 financial-regulation records from the
National Financial Regulatory Administration, and 500
environmental-regulation records from the Ministry of Ecology and
Environment. We sample up to 500 documents per domain and construct a small
field-level KG for each document. The evidence string is constructed by
serializing the nonempty structured fields as ``field name: value, joining
them with Chinese sentence separators, and truncating each field value to at
most 320 characters (the service label to 100). This is serialized-record
evidence, not an independent collection of unstructured document passages.
The same normalized field values define the reference triples. Documents are assigned by source identity to
train, validation, and test groups with a 70/15/15 split and seed 42 before
corruption, preventing clean/corrupted variants from crossing partitions.

Each controlled instance receives exactly two effective changes selected from
six classes: missing triple, duplicate triple, invalid relation, reversed edge,
unsupported value, and hierarchy conflict. The manifest records every clean
and corrupted triple. The held-out split contains 225 documents, balanced at
75 per domain, and 450 manifested defects (Table~\ref{tab:repair_benchmark}).
This protocol measures known repair obligations; it does not estimate their
natural prevalence.

\paragraph{Natural extraction errors.}
For the same 225 held-out sources, a fresh Claude Haiku call receives only the
source text, required document node, and relation vocabulary and constructs a
graph from scratch. It never sees the structured target, a corrupted graph, or
the injection manifest. The structured source fields define the reference
graph. Thus, discrepancies are produced by an actual extraction run and are
not selected from predefined defect templates. Ten malformed JSON responses
are retained as empty end-to-end outputs. Overall parse success is 95.56\%; 77
of 225 output graphs differ from the reference, with 302 multiset triple
discrepancies. This is a structured-reference evaluation; two-annotator human
adjudication of acceptable alternatives is not claimed.

\paragraph{Compared repair methods.}
All methods receive the same input graph, source evidence, required document
node, and relation vocabulary.
\begin{itemize}
    \item \textbf{Source-field Copy} parses declared field-name delimiters in
    the supplied evidence and reconstructs their values without a model call.
    It receives no reference tails or reference relation-presence set.
    \item \textbf{No Repair} returns the input unchanged.
    \item \textbf{Rule Only} deduplicates, reverses an edge when its object is
    the required document node, and removes invalid heads or relations.
    \item \textbf{SHACL-style Repair} applies canonical-head and
    allowed-predicate shapes \citep{ref_shacl2017}; it cannot reconstruct
    missing values from text.
    \item \textbf{Direct LLM} makes one source-grounded call and returns a
    complete graph.
    \item \textbf{ReAct-style Agent} makes a diagnosis call followed by an
    action call \citep{ref_yao2023react}.
    \item \textbf{Simple Pipeline} applies the same deterministic
    preprocessing as the diagnosis-plus-gate pipeline, makes one source-grounded call, and only
    deduplicates the response. It has no diagnostic report or candidate gate. Neither this baseline
    nor the archived Diagnosis + Gate invokes the sequential optimizer.
    \item \textbf{Diagnosis + Gate} uses diagnostic-context completion and rejects
    invalid-head, invalid-relation, unsupported, duplicate, and
    relation-cardinality proposals.
\end{itemize}

Unless stated otherwise, model-backed methods use the same served
\texttt{claude-haiku-4-5-20251001} checkpoint \citep{ref_anthropic_claude45},
temperature zero, and endpoint. Failures remain in the denominator. On the
controlled set, Direct LLM and Simple Pipeline each have one malformed JSON
response; the Diagnosis + Gate and ReAct have none.

\paragraph{Metrics and statistics.}
On the controlled benchmark, defect repair requires restoration of the clean
triple multiplicity and removal of its corrupted form. We also report
clean-fact preservation, over-repair, triple F1, exact multiset graph match,
calls, and latency. For a naturally extracted input $G_0$, output $G_1$, and
reference $G^*$, let $d$ be multiset symmetric-difference size. Natural-error
reduction is
\[
    1-\frac{d(G_1,G^*)}{d(G_0,G^*)},
\]
averaged over the 77 non-exact inputs; negative values mean that repair adds
more errors than it removes. Confidence intervals use 10,000 paired bootstrap
resamples for the new comparisons. Defect outcomes and exact graph matches use
exact McNemar tests as descriptive historical comparisons; the natural
error-count comparison additionally uses a one-sided paired Wilcoxon test.
For the current audit, paired bootstrap and two-sided sign-randomization tests
resample whole source documents (10,000 draws, seed 42), keeping the two
controlled defects of each document together. Mechanism comparisons are
reported individually as exploratory estimates; no family-wise significance
is claimed.

\subsection{Controlled Repair Results}
\label{sec:eval:overall}

The source-format baseline changes the interpretation of the main result:
Source-field Copy obtains 100\% repair and exact match with zero model calls.
Because the evidence explicitly serializes the reference fields, this baseline
can reconstruct them from declared delimiters. The benchmark therefore does
not establish a need for LLM repair or superiority over deterministic source
recovery. Comparisons among LLM pipelines below measure behavior within this
restricted task. Table~\ref{tab:repair_main} shows that Diagnosis + Gate repairs 98.00\% of
defects, preserves 99.32\% of clean facts, and reaches 99.17\% triple F1. The
strong Simple Pipeline reaches 95.11\% repair and 96.34\% F1 under the same
one-call budget. The Diagnosis + Gate uniquely repairs 15 defects missed by the
Simple Pipeline, while the reverse occurs twice (exact McNemar
$p=0.00235$). A document-paired reanalysis gives a repair-rate gain of
2.89 points (95\% CI: 1.11--4.89) and a two-sided randomization
$p=0.0067$; the corresponding F1 gain is 2.84 points (95\% CI:
1.65--4.25). Its gain therefore remains after introducing a strong
implementation-matched baseline, although that baseline closes much of the
gap over Direct LLM.

\subsection{Naturally Occurring Extraction Errors}
\label{sec:eval:natural}

Table~\ref{tab:natural_errors} evaluates actual extraction errors on the
serialized-record inputs. Source-field Copy again reconstructs all reference
graphs, so this protocol does not demonstrate generalization to unstructured
source text. Within the model-backed comparisons, the
unrepaired extraction output has 87.99\% F1 and 65.78\% exact match. The Simple
Pipeline changes few exact-match outcomes, but its mean error reduction on the
77 imperfect inputs is $-59.15\%$: aggressive completion introduces more
reference disagreements than it removes. In contrast, the Diagnosis + Gate reduces
errors by 27.75\%, preserves every initially correct fact on average, and
raises F1 to 92.48\%. Its paired F1 advantage over the Simple Pipeline is 4.40
points (95\% CI: 3.07--5.77), and it prevents 1.03 errors per document on
average (95\% CI: 0.77--1.32; one-sided Wilcoxon
$p=3.18\times10^{-12}$). Exact-match discordance is only three versus zero
and is not significant ($p=0.25$), so the evidence is stronger for partial
graph quality than for complete recovery.

\paragraph{Separating format failures from factual discrepancies.}
The 215 successfully parsed extraction outputs have 92.09\% initial F1,
compared with 93.53\% after Diagnosis + Gate and 88.85\% after the archived
Simple Pipeline. Among their 67 non-exact inputs, mean error reduction is
24.00\%; their F1 rises from 74.61\% to 79.22\%. All 148 initially exact parsed
graphs remain exact under Diagnosis + Gate. The ten malformed inputs recover
69.91\% F1 but none becomes fully exact. Thus the overall gain is not solely
JSON recovery, and the low exact recovery on imperfect parsed graphs remains
a substantial limitation.

\subsection{Component and Constraint-Gate Analysis}
\label{sec:eval:ablation}

The archived ablations reuse the same held-out run. Removing contextual
reasoning leaves deterministic preprocessing; removing preprocessing is the
same one-pass setting as Direct LLM; and removing the gate evaluates the exact
stored pre-gate proposal without another model call.

Contextual reasoning supplies most recovery, and structural preprocessing

of repaired manifested defects in this run, but lowers over-repair by 0.60

triples, all for absent source support, and all eight are non-reference facts;
it rejects no reference triple. This supports a conservative validation claim,
not a claim that the gate creates missing facts.

\subsection{Execution Audit and Matched Mechanism Comparison}
\label{sec:eval:router}
\label{sec:eval:mechanisms}

The archived results above were produced by one model call and the
\texttt{constrain\_output} filter. They did not execute the sequential optimizer
described in an earlier version of the method. We now replay the same frozen
proposals through the actual optimizer, using unchanged utility coefficients,
restoration bounds, and a 12-step horizon. Every trial graph and decision is
archived. On controlled inputs, both the learned-prior and always-on
uniform-prior variants accept zero additional edits, remaining at 32.00\%
repair and 84.72\% F1, the structural-preprocessing result. On natural inputs,
both reach 88.33\% F1 and 65.78\% exact match. A numerically clean profile can
miss incomplete fields, and proposed additions can have non-positive utility.
These results do not support the optimizer as the mechanism behind the
98.00\% pipeline repair rate.

\input{sections/audit_generated}

The new Gemma experiment uses the pre-existing fixed 60-document subset
(20 per domain) under both controlled and natural-input conditions. Three
context arms share one system prompt, deterministic preprocessing, temperature,
and completion cap. Each candidate response is scored before and after the
same gate. Table~\ref{tab:matched_mechanisms} reports all six combinations.
Input tokens and measured request wall time are reported separately; this is
a matched-call and matched-completion-cap comparison, not an equal-total-token
claim. The SHACL arm follows the documented adaptation in
Section~\ref{sec:impl:shacl}.

The matched experiment does not reproduce a diagnostic-context advantage.
After identical filtering, base context reaches 99.62\% controlled F1 and
97.50\% defect repair, versus 98.61\% and 92.50\% with diagnostics. The paired
F1 difference (diagnostic minus base) is $-1.01$ points (95\% CI:
$[-1.67,-0.38]$; exploratory randomization $p=0.0082$). On natural inputs,
base-plus-gate reaches 92.52\% F1, diagnostic-plus-gate 91.47\%, and the adapted
SHACL-context-plus-gate baseline 93.64\%. The diagnostic--SHACL difference
is $-2.16$ points (95\% CI: $[-5.26,0.02]$; $p=0.105$), so there is no evidence
of superiority over this constraint-aware baseline.

Filtering has a smaller, response-paired effect. Within diagnostic-context
natural outputs, F1 increases from 90.79\% to 91.47\%, a 0.69-point gain
(95\% CI: 0.20--1.29; exploratory $p=0.0335$), without changing exact match.
Across the 360 responses, the gate rejects 27 candidate occurrences, all
non-reference triples. It cannot restore an absent candidate. These results
support a limited validation role and show that extra diagnostic context is
not reliably beneficial. All settings are retained; we do not select a new
winning prompt on this held-out subset.

Earlier routing and leave-one-domain-out results used the set of relations
present in the reference graph to construct a missing-field feature. That
information is unavailable to a general deployment. We withdraw those results
as evidence of reference-free routing generalization. The replacement
violation-policy replay uses only observable head, predicate, duplicate,
cardinality, and source-support checks. It is a counterfactual selection of
archived repair outputs, not a measurement of online scheduling latency.
On the 450-item natural/clean stream, the reference-free visible-violation
policy routes 6.22\% of inputs but misses 63.64\% of imperfect graphs;
its output F1 is 94.46\%, compared with 95.82\% for always calling repair.
The always-call policy remains the main method because visible violations do
not reveal every missing or incorrectly assigned field.

\subsection{Diagnostic Batch Scaling}
\label{sec:eval:scale}

We time the input-derived diagnostic report in
Eq.~(\ref{eq:diagnostic_context}) on disjoint batches containing 1K--50K
triples. A full pass visits every document; a local update recomputes one
changed document. Full times are medians of seven runs and local times of
200 runs. Table~\ref{tab:diagnostic_scaling} reports the measurements.
The memory figure is peak new Python allocation for batch construction,
with source text and schema objects shared; it is not process RSS or the

\subsection{Secondary Checks}
\label{sec:eval:external_benchmark}

An independent Gemma judge evaluates 180 source--triple pairs without method
identity. Its source-support score correlates with exact reference validity at
Pearson $r=0.794$ and Spearman $\rho=0.807$ (both
$p<2.4\times10^{-40}$). A fixed 50-item subset produces the same mean, 0.96,
in five additional runs. This measures service repeatability and does not
replace human annotation.

We also compare the extraction path with Neo4j Labs' reproducible
\texttt{LLMGraphTransformer} core on 45 balanced TNEWS documents
\citep{ref_neo4j_llm_graph_builder}. Category accuracy is 0.556 for our
schema-guided extractor and 0.533 for Graph Builder; paired outcomes do not
differ ($p=1.00$). TNEWS has no gold triples, so this supports only comparable
behavior under that extraction protocol.

\subsection{Failure Analysis and Limitations}
\label{sec:eval:failure}

On controlled defects, all nine unresolved cases occur in long government
legal or procedural fields: three invalid relations, two missing triples, one
reversed edge, and three wrong values. Exact span recovery is therefore a
clear remaining failure mode.

The deterministic source-field baseline is the strongest limitation: both
protocols permit complete recovery by parsing the supplied source format.
An independently annotated corpus of unstructured passages is needed before
claiming an advantage of LLM-based repair over source reconstruction.

The extraction-error results expose further limits. Only 27.75\% of reference
discrepancies are removed on average, and exact match rises from 65.78\% to
68.44\%. The structured fields provide a schema-specific silver reference for this
document schema, but acceptable alternative triples have not yet received
two-annotator human adjudication. The extractor and primary repair model are
the same Claude checkpoint, the archived cross-model comparison covers only 60 controlled
cases, and the public TNEWS data lack gold triples. The original router used reference-derived features and is not retained as deployment evidence. Finally, the evaluated graphs are document-level field
graphs; cross-document entity alignment, causal chains, and production-scale
interconnected-KG repair remain outside the supported claims.

\subsection{Reproducibility and Availability}

The code, prompt templates, manifests, raw responses, model identifiers, parsing status,
case-level predictions, statistics, and scaling measurements are available at
\url{https://github.com/turambar928/MCP_based_KG_construction}. The new Gemma run checkpoints every completed request, including malformed outputs and transport failures. Aborted rate-limited batches are archived separately and are excluded wholesale from the matched comparison. The natural-error
annotation sheet and a separate blind system-edit audit are frozen with their sampling seeds and SHA-256 fingerprints;
human-label columns remain explicitly unfilled until two independent
annotators complete them. Credentials are read from an ignored local file and
are absent from the released experiment artifacts.
