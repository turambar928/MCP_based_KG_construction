\section{Evaluation}
\label{sec:eval}
\label{sec:experiments}

We organize the evaluation around a paired, instance-level repair benchmark. The benchmark supplies a clean target for every corrupted graph and records every injected defect, so repair success and collateral edits can be measured directly. Earlier corpus-level quality scores and a public Text-to-KG comparison are retained as secondary evidence.

\subsection{Experimental Protocol}
\label{sec:eval:setup}

\paragraph{Source data and paired benchmark.}
The source corpora contain 4,728 government-affairs records from the Shaanxi Provincial Government website, 1,000 financial-regulation records from the National Financial Regulatory Administration, and 500 environmental-regulation records from the Ministry of Ecology and Environment. We sample up to 500 documents per domain and construct a small field-level KG for each document. Before corruption, documents are assigned by source identity to train, validation, and test groups using a 70/15/15 split and seed 42. Consequently, a source document and its corrupted counterpart cannot occur in different splits.

For every document, the corruption procedure makes exactly two graph changes selected from six defect classes: missing triple, duplicate triple, invalid relation, reversed edge, unsupported value, and hierarchy conflict. A mutation is counted only when it changes the graph; document identifiers are never corrupted. The released manifest stores the document id, defect id and type, clean triple, and corrupted triple. Table~\ref{tab:repair_benchmark} summarizes the resulting benchmark. The held-out test set contains 225 documents, balanced at 75 per domain, and 450 manifested defects.

The test defects comprise 79 missing triples, 73 duplicates, 77 invalid relations, 71 reversed edges, 74 unsupported values, and 76 hierarchy conflicts. This controlled design measures repair capability under known faults; it does not estimate the natural prevalence of these faults in the source portals.

\paragraph{Compared methods.}
All methods receive the same corrupted triples, source evidence, required document node, and allowed relation vocabulary.
\begin{itemize}
    \item \textbf{No Repair} returns the corrupted graph unchanged.
    \item \textbf{Rule Only} performs exact deduplication, reverses edges whose object is the required document node, and removes triples with an invalid head or relation.
    \item \textbf{SHACL-style Repair} applies canonical-head and allowed-predicate shapes \cite{ref_shacl2017}. It validates and removes violations but cannot reconstruct missing or corrupted values from text.
    \item \textbf{Direct LLM} makes one source-grounded repair call and returns a complete graph.
    \item \textbf{ReAct-style Agent} first asks the model to diagnose the graph with a deterministic tool report and then makes a second call to execute the repair, following the diagnose--act pattern of ReAct \cite{ref_yao2023react}.
    \item \textbf{Ours} runs structural preprocessing, source-grounded contextual completion, and a final constraint gate that enforces the required head, relation vocabulary, evidence support, deduplication, and relation cardinality.
\end{itemize}

The three model-backed methods use the same served \texttt{claude-haiku-4-5-20251001} checkpoint \cite{ref_anthropic_claude45}, temperature zero, and the same API endpoint. Thus, their differences arise from the repair procedure rather than the base model. All 225 outputs from Ours and ReAct are valid JSON. Direct LLM returns invalid JSON on one long government document after the fixed retry policy; we retain that empty output as an end-to-end failure instead of deleting the case.

\paragraph{Metrics and statistical analysis.}
The primary metric is \emph{defect repair rate}: the fraction of manifested defects for which the clean triple multiplicity is restored and the corrupted form is removed. We also report clean-fact preservation, over-repair rate, triple precision/recall/F1, exact graph match, calls per document, and wall-clock latency. Preservation measures clean input triples that survive repair. Over-repair is the fraction of actual edits that are unnecessary relative to the paired clean target. Exact graph match requires multiset equality with the clean graph. The earlier four-dimension $Q_{score}$ is reported only as an auxiliary diagnostic because its semantic and structural components are less direct than paired triple correctness.

We compute document-level means and 95\% confidence intervals with 5,000 bootstrap resamples (seed 42). Defect-level comparisons between Ours and each baseline use an exact two-sided McNemar test on the same 450 defects. No test cases are used to select prompts or thresholds.

\label{sec:eval:overall}

Direct LLM is the strongest baseline, with a 92.44\% repair rate and 82.67\% exact match, but it makes more unnecessary changes: its over-repair rate is 7.58\%, compared with 1.67\% for Ours. Context reasoning supplies most of the recovery beyond deterministic faults: removing it lowers repair from 98.00\% to 32.00\%. \subsection{Repair Router Sanity Check and Efficiency}
\label{sec:eval:router}

The decision network $f_\phi$ is trained on the benchmark's paired clean/dirty rows using eight assessment and graph features. The MLP has architecture $8\!\rightarrow\!32\!\rightarrow\!16$ with a sigmoid repair head and a three-class scale-prior head (884 parameters). Training uses Adam at $0.005$, the combined BCE and masked cross-entropy loss, seed 42, and the preassigned document-group split: 2,098/450/450 rows for train/validation/test. No document identity overlaps across partitions.

On this controlled mapping, both repair-trigger accuracy/F1 and scale-prior top-1/macro-F1 are 1.000. We treat this result as a sanity check that the implemented router can learn the injected-defect labels, not as evidence that it will recognize naturally occurring defects perfectly. The held-out set is balanced between clean and corrupted rows, so the router sends 50\% of rows to repair. Combining this measured gating fraction with the observed full-system mean of one call and 11.445 seconds per repaired document gives 0.50 calls and 5.722 seconds per input, with no missed injected defect. This is a cost projection from measured components rather than a second end-to-end run.

\subsection{Independent Semantic Reliability Check}
\label{sec:eval:semval}

Triple correctness is computed against the clean target and does not depend on an LLM judge. We nevertheless test whether a separate model agrees that the generated triples are supported by their source. We sample 180 output triples with seed 42, balanced across the three domains and between No Repair and Ours. The judge, \texttt{google/gemma-4-26B-A4B-it} \cite{ref_gemma3}, receives only the source evidence and triple; method identity and gold labels are hidden. It scores full source support on $[0,1]$.

The judge score correlates with exact gold validity at Pearson $r=0.794$ and Spearman $\rho=0.807$ (both $p<2.4\times10^{-40}$). The mean score is 1.000 for Ours and 0.917 for No Repair. To quantify service stability, a fixed 50-item subset is judged five additional times at temperature 0.1. Every run has the same mean, 0.96; both the mean item-level standard deviation and the standard deviation of run means are 0.0. These results concern repeatability under this served checkpoint and sample, and do not replace human evaluation.

\subsection{External Text-to-KG Comparison}
\label{sec:eval:external_benchmark}

The main experiment evaluates repair given a corrupted graph. To compare the broader extraction path with a public Text-to-KG application, we additionally use Neo4j Labs' LLM Knowledge Graph Builder \cite{ref_neo4j_llm_graph_builder}. We invoke its reproducible core, \texttt{LLMGraphTransformer} from \texttt{langchain-neo4j==0.10.0} at repository commit \texttt{5ff7af3e}, rather than manually operating the website. Both systems process the same 45-document balanced TNEWS subset with \texttt{Qwen3.8-27B-no-thinking}, temperature zero, one worker, and identical category and relation vocabularies. TNEWS supplies category labels and weak entity keywords but no gold triples, so this is a controlled extraction comparison, separate from the paired repair benchmark.

\subsection{Failure Analysis and Limitations}
\label{sec:eval:failure}

The full system leaves nine of 450 test defects unresolved. The audit is exhaustive rather than a sample: all nine occur in government documents, comprising three invalid relations, two missing triples, one reversed edge, and three wrong values. In each case, the target field is a long legal citation or multi-stage responsibility description. The model either omits the field or fails to reproduce the exact source span and relation required by the strict matcher. Finance and environment have no unresolved manifested defect in this split.

This concentration identifies a concrete boundary: source grounding prevents invented replacements, but exact recovery becomes harder when one object contains a long statute or procedure. Chunk-aware copying or span selection is a more targeted next step than adding unconstrained generation. The benchmark also has three limitations. First, defects are injected and balanced, so natural error frequencies may differ. Second, exact matching can penalize semantically equivalent paraphrases, although administrative field values should generally be copied verbatim. Third, the same hosted base model is used for all model-backed repair methods; additional model families would test whether the observed ranking is model-independent.

\subsection{Reproducibility}
All benchmark cases, manifests, predictions, raw model responses, per-case and per-defect metrics, bootstrap summaries, McNemar tables, ablation outputs, semantic-judge outputs, and failure audits are archived with the code. API-backed runs checkpoint every ten cases. The benchmark fingerprint, random seeds, model identifiers, prompts, parsing status, call counts, and latency are stored in the experiment artifacts. Credentials are read only from an ignored local configuration file and are not written to outputs.
