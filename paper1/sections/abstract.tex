\begin{abstract}

Knowledge graphs constructed from text contain structural and source-grounding
errors that a single unconstrained language-model call may repair incompletely
or amplify. We study this problem for document-level knowledge graphs and
formulate repair as profile-conditioned candidate generation followed by
explicit feasibility checks. A four-dimensional profile summarizes
connectivity, uniqueness, logical consistency, and source support. Deterministic
rules and a source-grounded language model propose edits, while a constraint
gate rejects proposals with invalid heads or relations, unsupported values,
duplicates, or cardinality conflicts. On a controlled held-out benchmark of
225 document graphs and 450 manifested defects, the full system repairs
98.00\% of defects and obtains 99.17\% triple F1. A strong one-call pipeline
with the same preprocessing and base model reaches 95.11\% repair and 96.34\%
F1; the paired defect comparison favors the full system
($p=0.00235$). We additionally evaluate 225 graphs produced by an actual
text-to-graph extraction call, without injected defects. Seventy-seven graphs
differ from their structured source records. On this natural-error set, the
full system reduces errors by 27.75\% and reaches 92.48\% F1, whereas the
simple pipeline increases the error count and reaches 88.07\% F1; the paired
F1 advantage is 4.40 points (95\% bootstrap CI: 3.07--5.77). The constraint
gate rejects eight proposals, all non-reference unsupported triples. The
method ordering is preserved with Claude Haiku and Gemma on a fixed 60-case
subset. Learned routing matches transparent violation and threshold routers on
both controlled and natural streams, so we treat it as an optional policy
implementation rather than the source of the repair gain. Code, prompts,
predictions, and case-level statistics are released for reproduction.

\keywords{Knowledge Graph Repair, Constraint Validation, Document-Level Knowledge Graph, Large Language Models}

\end{abstract}
