\section{Implementation and Experimental Comparisons}
\label{sec:implementation}

\subsection{Repair Procedure}
\label{sec:impl:assessment}

Algorithm~\ref{alg:abstract} describes Diagnosis + Gate. The diagnostic report
and filter are deterministic; the language model proposes field values.

\begin{algorithm}[t]
\caption{Source-grounded document-graph repair}
\label{alg:abstract}
\begin{algorithmic}[1]
\Require Input multiset $G$, source $X$, document node $h_0$, relation vocabulary $\mathcal R_X$
\Ensure Repaired graph $\widehat G$ and rejection log $J$
\State $G_s\gets P(G;h_0,\mathcal R_X)$
\State $D\gets D(G_s,X)$
\State $C\gets\textsc{Parse}(L_\theta(X,h_0,\mathcal R_X,G_s,D))$
\State $\widehat G\gets\emptyset$; $J\gets\emptyset$; $B\gets\emptyset$
\For{each candidate $t=(h,r,o)$ in generation order}
    \If{$t$ appeared earlier in $C$}
        \State append $(t,\text{duplicate})$ to $J$
    \ElsIf{$H(t)R(t)S(t;X)=1$ and $r\notin B$}
        \State $\widehat G\gets\widehat G\cup\{t\}$; $B\gets B\cup\{r\}$
    \Else
        \State append $(t,\text{failed check})$ to $J$
    \EndIf
\EndFor
\State \Return $\widehat G,J$
\end{algorithmic}
\end{algorithm}

The runner passes the source, document node, allowed relations, and input
triples through a dedicated input object. References are loaded by the scorer.
Tests verify that changing reference values and defect labels leaves model
inputs unchanged. The document node is task metadata; the legacy data loader
reads its identifier from the reference record.

With hash-based schema and duplicate checks, preprocessing takes expected
$O(|G|)$ triple operations. Filtering $k$ candidates costs $O(k(1+c_X))$,
where $c_X$ is the cost of literal source matching, and uses
$O(k+|\mathcal R_X|)$ auxiliary storage. String operations depend on text
length; model inference is measured separately.

\subsection{Matched Context and Filtering Comparisons}
\label{sec:impl:enhancement}

We use one system prompt with three context settings: base input, base plus
diagnostics, and base plus SHACL validation. Scoring each response before
and after filtering gives six configurations from three model calls per
input. The raw/gated pair shares exactly the same candidates.

The matched experiment uses \texttt{google/gemma-4-26B-A4B-it}, temperature
zero, and a 4,000-token completion cap. Call counts and completion caps are
the same across settings. We report input tokens separately because the
contexts differ in length. Request times include recorded retries and pacing
waits. Each completed outcome is stored; malformed responses remain in the
evaluation. The earlier Claude comparison uses method-specific prompts and
measures whole-pipeline differences.

\subsection{SHACL-Context Baseline}
\label{sec:impl:shacl}

Lin et al.\ use five prompt components: a primer, violation context, SHACL
manifest, graph context, and instructions \citep{ref_lin2025}. We adapt their
full-manifest/full-graph ($M+G$) configuration to document-field repair.
The pySHACL validator checks the document head, allowed predicates, nonempty
values, and maximum field counts. A SPARQL constraint checks whether values
occur in the source text.

The adapted baseline returns complete JSON graphs, includes the source text,
and groups a document's violations into one call. These choices match our
task and call budget. We call it \emph{Lin-style SHACL context (adapted)}.
RDF stores unique triples; the shared JSON input also preserves duplicate
occurrences. We score both raw and filtered outputs for every context setting.

\subsection{Sequential Selection Comparison}
\label{sec:impl:optimizer_audit}

We also evaluate the repository's sequential selector on fixed model
proposals. This alternative uses a four-score quality profile, a learned
scope prior, and a utility score to choose an edit at each step. Each proposed
edit bundle is applied to a trial graph, which is checked against the
restoration bounds before acceptance. Differences between the normalized
input and candidate graph define one edit bundle per relation. Proposal
confidence is 0.7; the horizon is 12 steps. We compare the learned prior with
an always-on uniform prior using the default utility coefficients.

The trace records every trial graph, quality profile, utility, decision, and
stopping reason. Source matching removes whitespace from both the source and
candidate value. The archive also retains traces from the earlier asymmetric
normalization for reproducibility. This selector is evaluated separately
from Algorithm~\ref{alg:abstract}.
